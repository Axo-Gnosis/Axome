# Other harnesses: login, credential provenance, unavailable models

Research snapshot: 2026-11-20. Source inspection, not live login testing. Questions B1, B2, U1 and C2's saved-but-unentitled-model case only. No Axome/axo source changes.

## Source versions and important drift

Commit-pinned links below refer to pi `06a20368a74233e21725511a3268742e3dea65c3`, OMP `fbb8085ff432419132c6e3132f36ad857893b1a4`, OpenCode `504a7b3054491b99fc1b11cf83be6fae836ef77c`, Codex `0a0b1021f06dffda763bdafbee32e25c04cac20b`, Zed `34639504475cef1677149ad351b3788a89dba865`. Two material changes from the question's starting description:

Its named `OAuthLoginCallbacks` now survives as an extension-compatibility interface, including device code and select; built-ins use `ProviderAuthInteraction` ([interface](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/ai/src/compat/extension-oauth-types.ts#L16-L46)).

## B1 — Interaction kinds and remote/headless presentation

### Evidence

**pi**
- TUI replaces the editor with a login component. Auth URL is displayed, copied through a keyboard action, and best-effort opened; optional instructions remain visible. Device flow renders verification URL plus user code; Enter can **copy code and open browser**, with success/failure copy feedback. Device expiry exists in the callback type but the inspected rendering does **not render an expiry countdown**. Manual-code/redirect input, appended sequential prompts, progress lines, waiting state and Escape cancellation are implemented. Cancellation aborts the signal and rejects pending input. [Dialog implementation](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/modes/interactive/components/login-dialog.ts#L115-L328).
- Select is a separate selector component mapped back to option IDs. Important caveat: the TUI prompt dispatcher routes everything except select/manual-code to plain `showPrompt(message, placeholder)`; it does **not preserve the secret discriminator**. Do not copy that as a secure generic GUI contract. The standalone auth CLI *does* route secret prompts to masked terminal input. [TUI dispatcher](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/modes/interactive/interactive-mode.ts#L6503-L6590), [CLI](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/cli/auth-login.ts#L164-L168).
- Anthropic currently offers **Browser login / Copy code login (headless)**, not a Pro/Max-versus-Console selector. Copilot first asks for **GitHub Enterprise URL/domain (blank for github.com)**, then emits structured device code, polls, fetches account models and reports “Enabling models...” when applicable. [Anthropic](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/ai/src/auth/oauth/anthropic.ts#L278-L299), [Copilot](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/ai/src/auth/oauth/github-copilot.ts#L428-L478).

**OMP**
- Same overall interaction family, now a TUI overlay plus native sheet. Full authorization URL is the primary remote-safe copy target; a short loopback launch URL is explicitly labeled **“Local shortcut (this machine only)”**. Source comments explain why using the short localhost link from SSH/WSL fails and why wrapping must not truncate OAuth query parameters. It opens the full URL best-effort. [URL presentation](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/login-dialog.ts#L159-L213).
- Sequential prompts preserve prior non-secret answers, substitute `********` for prior secrets, and replace the field to discard secret undo/yank history. Manual paste retries show “Couldn't read a code ... paste ... code or full redirect URL.” Escape aborts/rejects. [Prompt handling](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/login-dialog.ts#L151-L156), [manual and secret input](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/login-dialog.ts#L219-L303). The callback contract says hosts unable to hide a secret **must reject** the prompt ([types](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/ai/src/registry/oauth/types.ts#L58-L68)).
- Native sheet has a click-to-copy code well, URL field with Copy, sequential questions/progress, Cancel and Continue/Open Browser actions. Device code is extracted from provider instructions rather than a generic structured expiry UI; no countdown is evidenced here. [Native rendering](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/login-dialog.ts#L337-L471).
- Gemini CLI uses callback `127.0.0.1:8085/oauth2callback`; Antigravity's retained-but-disabled definition uses `127.0.0.1:51121/oauth-callback`. Both include post-token project-discovery hooks: token exchange need not be the final stage. Gemini reports project checking/provisioning progress. Anthropic explicitly instructs remote users to paste final redirect URL or authorization code. [Gemini definition](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/catalog/src/compat/rules/auth/google-gemini-cli.kdl#L1-L25), [Gemini progress](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/ai/src/registry/oauth/google-gemini-cli.ts#L103-L214), [Anthropic instructions](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/catalog/src/compat/rules/auth/anthropic.kdl#L9-L19).

**OpenCode CLI and desktop/web app**
- CLI selects login method, masks API key input, prints authorization instructions+URL, opens browser only for interactive TTY, asks for a code in code mode, otherwise waits for authorization. Automatic mode can **race completion with a pasted redirect URL**, whose prompt explicitly covers a browser unable to reach this machine. A scope finalizer cancels the server-side attempt; long waits avoid a spinner that would intercept Ctrl+C and skip cleanup. [CLI flow](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/cli/src/commands/handlers/auth/login.ts#L103-L231), [paste loop](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/cli/src/commands/handlers/auth/login.ts#L275-L296).
- App code-mode view has a code field, Open Browser, Continue. Auto-mode view shows a **copyable confirmation code** where supplied, browser-launch failure, and optional redirect-paste disclosure. **Paste is expanded by default for a remote server** (`paste.open ?? onRemote`). This is a particularly direct precedent for remote axome-server. [App views](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/providers/connect/dialog.tsx#L1010-L1103).
- API-key and code entry use the same `EntryField`; the inspected caller sets autocomplete off but does **not explicitly request password masking**. CLI masking must not be generalized to the app. [Entry field](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/providers/connect/dialog.tsx#L938-L1006). No expiry countdown was found in these code/device views.

**Codex CLI**
- ChatGPT browser login uses localhost port **1455**; browser screen explicitly says remote/headless users should press Escape and choose **Sign in with Device Code**. Cancellation calls the app-server's cancel-login endpoint, rather than merely dismissing the screen. [Browser screen](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/tui/src/onboarding/auth.rs#L754-L769), [cancellation](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/tui/src/onboarding/auth.rs#L131-L141).
- Device view renders hyperlink and one-time code, **static “expires in 15 minutes”**, preparing/waiting text, anti-phishing warning and Escape cancellation; no copy button or live countdown in that renderer. [Device UI](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/tui/src/onboarding/auth/headless_chatgpt_login.rs#L85-L168).
- Official headless guidance: prefer `codex login --device-auth`; fallback is authenticate on a browser machine and transfer cached `auth.json`, or tunnel **`ssh -L 1455:localhost:1455 user@remote`** and run browser login in that SSH session. These are documented alternatives, not a claim that plain localhost callback works remotely. [Official auth guidance](https://learn.chatgpt.com/docs/auth#login-on-headless-devices) (redirect destination of developers.openai.com/codex/auth).

**Claude Code**
- Official docs: browser opens on first launch; press **c** to copy URL if it fails; paste browser-displayed code into **“Paste code here if prompted”**; terminal reports success and asks Enter. Account types include claude.ai subscriptions/Teams/Enterprise, Console, and third-party platforms. Current Console flow can itself select **keep OAuth profile (recommended) / create API key (legacy)**. This demonstrates that a login can produce either an OAuth credential or a key. `/logout` resets first-launch setup. [Authentication](https://code.claude.com/docs/en/authentication#log-in-to-claude-code), [Console alternatives](https://code.claude.com/docs/en/authentication#sign-in-without-an-api-key).
- Paste-code is documented; exact current SSH-specific callback racing, countdown and cancel internals are **unverified** (closed implementation). Do not infer an automatic device flow or port-forward requirement from the existence of browser login.

**Zed**
- Copilot Chat modal displays subscription requirement, a code with **Copy / Copied!**, instructions, **Connect to GitHub** button changing to **Waiting for connection...**, and Cancel. Connect opens provider verification URI. No countdown in the inspected renderer. Cancel emits modal dismissal; that alone does not establish server-side cancellation of an already-issued device grant. [Copy control](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/copilot_ui/src/sign_in.rs#L568-L590), [modal](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/copilot_ui/src/sign_in.rs#L593-L643).
- [INFERENCE] A device verification URL/code is usable in a browser on another machine because it is not a loopback redirect; the modal itself does not supply SSH-forwarding guidance.

### Options seen

1. **Callback plus concurrently usable paste fallback:** pi/OMP family and OpenCode; OpenCode exposes paste by default remotely. Keep original authorization URL available even if browser launch fails.
2. **Provider-supported device flow:** Copilot in pi/Zed and Codex's explicit headless choice. Display verification URL and user code distinctly; copy affordance is common, a live expiry countdown is **not** a universal precedent. A host cannot invent device authorization for a provider that does not implement it.
3. **Explicit remote workaround:** Codex documents SSH forwarding and credential transfer when device auth cannot be used. These differ operationally from browser/paste and need explanation, not silent substitution.
4. **Generic interaction state machine versus provider-specific screens:** pi/OMP generic prompts/progress; OpenCode method/attempt views; Zed purpose-built Copilot modal. Selection and sequential prompts have actual uses; a single “open browser and wait” modal cannot reproduce these flows. Secret input must remain semantically distinct (OMP explicitly enforces this), even though some inspected clients lose that distinction.

## B2 — Capability, configured state, provenance, and removal

### Evidence

- **pi:** picker distinguishes **API key / subscription / account**, then separately **not configured**, configured by another auth kind, configured, or **env: VARIABLE**. A method can be offered while another method currently authenticates the provider. [Picker type/status](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/modes/interactive/components/oauth-selector.ts#L18-L57). Copilot concretely declares both key auth (`COPILOT_GITHUB_TOKEN`) and OAuth in the same provider ([provider definition](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/ai/src/providers/github-copilot.ts#L24-L42)). Thus “can log in” and “has credentials” are independent axes.
- **OMP:** credential provenance vocabulary is **--api-key / config / login / api key / env**. Native provider cards say **Not configured**, **Signed in · source**, or **API key · source**; validity can additionally be checking/invalid/valid. Login lists supported login entries; logout lists only providers with **stored credentials**, not everyone with a resolved env key, and includes now-disabled providers so old credentials can still be removed. [Source labels](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/oauth-selector.ts#L56-L63), [logout filtering](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/oauth-selector.ts#L169-L194), [cards](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/oauth-selector.ts#L474-L515). Login may return OAuth credentials **or a string key** ([contract](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/ai/src/registry/oauth/types.ts#L121-L130)).
- **OpenCode:** method selection can offer key and OAuth under one integration. Environment-only integrations have no interactive methods and get an explicit environment-only screen. Stored accounts have Remove confirmation; removing the final account disconnects the integration. [CLI method selection](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/cli/src/commands/handlers/auth/login.ts#L103-L128), [environment-only state](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/providers/connect/machine.ts#L376), [account removal semantics](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/providers/connect/dialog-machine.ts#L538-L560). Do not treat “Remove account” as unsetting a server environment variable.
- **Zed:** API-compatible settings show key editor when unauthenticated, otherwise a success check with **API key set in VARIABLE environment variable** versus **API key configured for URL**. Reset API Key gives env-backed keys a tooltip instructing the user to unset the variable. Loading credentials has a distinct state. Copilot reset is deliberately **sign out**, not a fake key editor. [API-key settings](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_models/src/provider/api_compatible.rs#L203-L274), [Copilot reset](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_models/src/provider/copilot_chat.rs#L179-L188).
- **Claude Code:** env API key is explicitly approved once in interactive mode; `/config` can toggle its use, `/status` distinguishes active and inactive credentials. `/logout` removes/revokes stored login; it does not imply removal of inherited env variables. Credential precedence and account-type policy are independent of offering `/login`. [Credential precedence](https://code.claude.com/docs/en/authentication#authentication-precedence), [Console logout](https://code.claude.com/docs/en/authentication#sign-in-without-an-api-key).
- **Codex:** ChatGPT browser/device login and API key are alternative authentication methods rather than a universal multi-provider credentials-card system. Its official auth page documents sign-in method and credential storage; do not extrapolate pi's per-provider provenance badges to Codex. [Official authentication](https://learn.chatgpt.com/docs/auth).

### Options seen

1. **Orthogonal method + status + source:** most explicit in pi/OMP. A login-capable provider can currently be authenticated by env/config/key; OAuth capability is not a configured-status bit.
2. **Provider-specific configuration UI:** Zed (Copilot sign-in/out, other providers key/reset) versus OpenCode's method list and stored-account manager.
3. **Removal restricted by ownership:** OMP logout offers stored credentials only; Zed explains env unsetting. Removing an app-owned credential cannot promise the provider becomes unauthenticated when another source remains.
4. **Both key and login on one provider:** directly demonstrated by pi Copilot, OpenCode methods and Claude Console. Exclusive “Login OR key field based on provider kind” is not a faithful generic capability model.

## U1 and C2 — Saved/current model disappears or account lacks access

### Evidence

**pi: startup fallback; resumed-session fallback with message; account filtering**
- Saved default is used only if found and provider auth is configured; otherwise select a known provider default among available models, then first available. This default-resolution path returns **no fallback message**. [Default resolver](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/core/model-resolver.ts#L569-L602).
- Restoring a conversation differs: model missing or auth absent produces **“Could not restore model provider/id”**, runs initial resolution and appends **“. Using provider/id”**; no available model produces the no-models message. [Session restoration](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/core/sdk.ts#L223-L250). This is not evidence that every in-flight logout silently switches models.
- **Account availability is real, not just credentials-present:** Copilot login fetches account model IDs before returning; OAuth credentials carry `availableModelIds`; provider model filtering intersects catalog models with that set. If this metadata is absent, it returns the unfiltered catalog instead, so catalog visibility is not an entitlement guarantee. [Login model discovery](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/ai/src/auth/oauth/github-copilot.ts#L450-L478), [filter](https://github.com/earendil-works/pi/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/ai/src/providers/github-copilot.ts#L34-L42).

**OMP: policy-gated restore fallback, stricter noninteractive contract**
- Session restoration checks both model existence and actual key resolution, distinguishes **“model no longer exists” / “no API key available”**, then returns current-model or available-model fallback with explicit warning. [Resolver](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/coding-agent/src/config/model-resolver.ts#L2578-L2636).
- Crucial host-level gate: saved models must first be unrestorable **even after discovery**; fallback is allowed only with UI, `retry.modelFallback`, and `allowSessionModelFallback`. Otherwise creation/session switching throws **“Could not restore model ...”**. RPC-UI hosts unable to show the warning are told to disable fallback. [SDK contract](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/coding-agent/src/sdk.ts#L1020-L1030). A helper supporting fallback does not mean every caller permits it.
- Saved-default resolution separately falls through to first available when the configured model is not found, with no fallback message returned. [Initial resolution](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/coding-agent/src/config/model-resolver.ts#L2556-L2575).

**OpenCode app: preserve explicit choice, show unavailable**
- Valid fallback candidates require both catalog model presence and connected provider. Defaults use configured → recent → first connected-provider model. But **explicit chosen/durable model key is retained even when the catalog no longer offers it**, specifically to prevent a next-send silent switch. Lookup of that key can return no current model. [Selection](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/providers/models/selection.tsx#L361-L404), [retention](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/providers/models/selection.tsx#L463-L480).
- Composer shows **“modelID (unavailable)”** instead of replacing the explicit choice. Submission's selection snapshot returns nothing when model or agent is absent. This establishes no silent replacement and a missing-model submission barrier at that layer; it does not establish every top-level send-error string or picker-grey-row behavior. [Label](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/composer/composer.tsx#L35-L47), [submission selection](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/composer/submit.ts#L633-L644).

**Codex: preserve explicit model, metadata fallback is not execution fallback**
- General model manager returns a supplied model string unchanged; only absence chooses a default from available models. Unknown slugs get **fallback metadata**, with a tracing warning. This does not mean a different model ID is substituted. [Selection contract](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/models-manager/src/manager.rs#L308-L337), [unknown metadata](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/models-manager/src/model_info.rs#L97-L108).
- Static/provider manager supports a distinct opt-in `allow_provider_model_fallback`: preserve available requested model, otherwise choose default. Without opt-in, preserve the requested string. [Implementation](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/models-manager/src/manager.rs#L1136-L1162). Therefore “Codex always silently fixes an account-unavailable model” is false.
- The account can still reject a model at request time. Source regression scenario uses **“The '...' model is not supported when using Codex with a ChatGPT account.”** Its special recovery concerns compaction against a retired *previous* model after a rename, not universal selected-model migration. [Regression scenario](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/core/tests/suite/compact.rs#L3249-L3279). Exact current TUI handling of arbitrary entitlement rejection is not established by this test alone.

**Zed: auto fallback only without an explicit user default**
- Agent initialization enables fallback only when raw user settings have **no agent.default_model**. Registry fallback is the first authenticated provider's default/recommended model, and applies only when no resolved default exists and fallback is enabled. Thus a vanished explicitly configured default is not automatically replaced by an unrelated authenticated provider through this mechanism. [Settings gate](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/agent_ui/src/agent_ui.rs#L978-L1011), [fallback selection](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_model/src/registry.rs#L392-L408), [default access](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_model/src/registry.rs#L470-L482).
- Configuration errors distinguish **NoProvider / ModelNotFound / ProviderNotAuthenticated**. Logout is therefore not semantically the same as catalog disappearance. Exact current agent-panel visual treatment for every disappearance path is not established by this registry code. [Error classification](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_model/src/registry.rs#L266-L285).

**Claude Code: explicit policy-dependent fallback, not one universal rule**
- Official docs describe configurable fallback chains for unavailable/overloaded models, notice on switch, and **current-turn-only** switch. Authentication/billing/rate-limit/request-size/transport failures do not trigger it. Bedrock/Vertex model-access refusal can count as unavailable rather than authentication failure. Chain is not confirmed at startup or shown in `/status`; first switch notice is the first visible indication. [Fallback chains](https://code.claude.com/docs/en/model-config#fallback-model-chains).
- Third-party default-model startup checks can notify and fall back to an earlier default, or Sonnet when no Opus is available; explicit version pins change/skip the default check. This is not automatic generic rename repair for arbitrary saved IDs. [Pinning and startup checks](https://code.claude.com/docs/en/model-config#pin-models-for-third-party-deployments).
- Expired login without another credential causes requests to fail; `/status` can show **Expired — log in again**. Another configured credential may be used instead, billed to its organization. That is **credential fallback**, not necessarily model fallback. [Expired login](https://code.claude.com/docs/en/authentication#after-the-login-expires).

### Options seen

1. **Fallback silently for an unresolved default:** pi and OMP initial-default resolvers. Different from a user's explicit current session choice.
2. **Fallback with a visible restore warning:** pi resumed sessions; OMP only with explicit host/UI policy permission. OMP refuses this for hosts unable to display the warning.
3. **Retain explicit choice and mark unavailable / require intervention:** OpenCode app; Zed prevents automatic registry fallback when user configured a default. This preserves intent rather than merely keeping sends operational.
4. **Keep unknown model ID and let provider adjudicate:** Codex's ordinary explicit-model path, using fallback *metadata*, not a substitute execution model. Useful distinction for custom/new IDs absent from a catalog; catalog absence is not equivalent to account denial.
5. **Explicit runtime fallback policy:** Codex static-provider opt-in and Claude Code configured chains. Failure class and notice semantics are part of the policy, not an accidental catch-all.
6. **Account-specific filtering before selection:** pi Copilot demonstrates login returning account model IDs and catalog intersection. Missing entitlement data can still leave a model visible; neither credentials-present nor catalog membership proves permission. For C2, distinguish known absence in a successfully fetched account list from unknown availability while discovery failed/not yet completed.

No single winner is forced by these precedents. The strongest repeated boundary is **default selection versus explicit/restored user intent**, and the separate dimensions **catalog existence, credential presence, credential validity, account entitlement**. No inspected universal mechanism safely maps every removed/renamed model to a successor. Goose was omitted as optional; no claims are made about it.
