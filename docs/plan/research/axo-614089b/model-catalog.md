# Model catalog inventory — axo a0ec20d..614089b — 2026-11-20

Scope: `614089b` catalog/session adoption changes and `0f4f890` model-registry changes. Paths beginning `crates/` refer to axo at `614089b`; `src/` and `src-crates/` refer to Axome. Source inspection only; no builds or tests run. Uncommitted axo roadmap files are excluded.

## 1. What changed in axo

### Public metadata shape versus metadata source

- **No `Model`, `InputKind`, `ApiKind`, `Cost`, `CostTier`, `UsageCost`, or thinking-helper schema migration in this range.** The diff for `src/{model,cost,thinking,types}.rs` under `crates/axo-ai/` is empty. `Model` still carries `reasoning`, `thinking_level_map`, `input`, `cost`, `context_window`, `max_tokens`, `compat`, API and identity; API variants remain Anthropic Messages, OpenAI Completions, and OpenAI Codex Responses; input remains Text/Image (`crates/axo-ai/src/model.rs:12-76`). What changes is how the registry populates these fields, and how long-lived sessions adopt them.
- The old `https://models.dev/api.json` feed and `models.dev.json` cache become **`https://models.dev/experimental/v2.0/api.json`** and **`models.dev.v2.json`**. Old cache files are not read by the new reader. Fetch timeout changes from 15 to 30 seconds (old source `a0ec20d:crates/axo-ai/src/models/catalog.rs:13-16`; new `crates/axo-ai/src/models/catalog.rs:14-16,153-162,190-201`).
- Feed structure now has model `type`, `capabilities.tools.supported`, `capabilities.reasoning.{supported,effort,toggle,budget}`, `recommended_api`, per-API `base_url`/`sdk.aisdk`/capabilities, and nested `cost.text.{input,output}` rates and overrides. Missing fields default; malformed providers/models are skipped (`crates/axo-ai/src/models/catalog.rs:24-151,217-232`; `crates/axo-ai/src/models/rules.rs:173-190`).
- Catalog inclusion is **data-driven**, replacing the former provider table and per-model-id metadata rules: a row must be a tool-capable `chat`, recommend `messages` with `@ai-sdk/anthropic` or `chat-completions` with `@ai-sdk/openai-compatible`, and have a resolvable URL. Unsupported recommended APIs are skipped, not replaced with another entry. URL templates resolve through config-value rules; Anthropic `/v1` is stripped because its adapter appends `/v1/messages`. Thus catalog membership, endpoints, and capabilities can differ without any public type change (`crates/axo-ai/src/models/rules.rs:1-4,173-222`).
- Limits use positive `limit.context`, capped by positive `limit.input`; missing/nonpositive context falls back to 4096. Positive `limit.output` becomes `max_tokens`, otherwise 4096. Images are accepted for `image` or `image/*` input modalities. Anthropic temperature/system-update/effort-update/tool-list-update flags come from feed capabilities, with API-level flags taking precedence. Other compat fields remain default unless config patches them (`crates/axo-ai/src/models/rules.rs:224-293`).
- Effort strings now populate the existing thinking-level map. Known listed levels map to themselves; unlisted named levels are unsupported; unknown effort strings are ignored. `none` maps Off to `"none"`; toggle/budget support can leave Off unmapped. Anthropic reasoning with efforts but no budget uses adaptive thinking; budget thinking keeps the default level behavior (`crates/axo-ai/src/models/rules.rs:224-241,295-315`). `thinking::supported_levels(&Model) -> Vec<ThinkingLevel>` itself is unchanged: nonreasoning gives only Off, null map entries are unsupported, XHigh/Max require explicit mappings. Clamping chooses the requested level, else the next higher supported level, else the next lower, falling back to Off (`crates/axo-ai/src/thinking.rs:19-58`).

### Prices and context tiers

- Tiered pricing **already existed**, including public `Cost.tiers: Vec<CostTier>` and camelCase serialization. Rates remain USD per million tokens (`crates/axo-ai/src/model.rs:34-57`). New feed mapping reads base rates from `cost.text.input/output.price`, cache rates from input cache metadata, and overrides only when their sole condition is context `gt` or `gte`. `gte N` becomes `inputTokensAbove = N - 1` (saturating); service-tier/time/mixed conditions are ignored. Missing tier rates retain base rates, not the previous tier's rates. Cache-write TTL objects prefer `5m`, otherwise their first value (`crates/axo-ai/src/models/rules.rs:317-384`).
- Calculation remains request-wide, **not marginal bracket pricing**: total input for tier selection is `usage.input + cache_read + cache_write`; the greatest threshold strictly exceeded selects all four rates for the whole request. Component costs divide token-rate products by one million; 1h cache writes use twice the selected input rate; `UsageCost.total` sums the components and is stored in `usage.cost` (`crates/axo-ai/src/cost.rs:6-37`).
- Unless `extended_context` is true, initial catalog/Codex model windows are capped at their lowest price-tier threshold. Config overrides apply afterward, so explicit user limits still win (`crates/axo-ai/src/models/rules.rs:158-170`; `crates/axo-ai/src/models/mod.rs:674-686,739-810`; `crates/axo-ai/src/models/config.rs:146-160`). Prices/limits are rebuilt from refreshed data, affecting subsequent requests rather than rewriting previous usage records.

### Codex account list

- New authenticated discovery: `GET {base}/codex/models?client_version=999.0.0`, 15-second timeout, Bearer token, `originator: axo`, and account-id header when derivable. `/codex/responses` or `/codex` suffixes are normalized. Config provider base URL takes precedence over auth base URL and the built-in endpoint. Missing credentials skips discovery; other errors warn and preserve the previous list (`crates/axo-ai/src/models/codex.rs:29-33,62-127`; `crates/axo-ai/src/models/mod.rs:603-651`).
- Rows use `slug`, display name, positive context window, image modality, and supported reasoning efforts. Hidden rows (`visibility == "hide"`), malformed rows, and rows lacking positive windows are skipped; an entirely empty usable response is an error (`crates/axo-ai/src/models/codex.rs:41-127`). The account list **replaces**, rather than extends, the offline floor (`crates/axo-ai/src/models/rules.rs:127-155`).
- Without a discovered/cached list, seven fixed floor IDs remain: `gpt-6.1-sol`, `gpt-6-astra`, `gpt-6-sol`, `gpt-6-luna`, `gpt-5.6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`. Floor efforts are low/medium/high/xhigh/max, with Off support determined separately. Codex uses discovered/floor windows, **not** public API windows; max output is 128,000. Prices and Off support come from a same-ID OpenAI feed row, else the floor; unknown IDs without feed prices get zero/default prices. Floor prices include a tier above 272,000 input tokens (2× input/cache, 1.5× output). Codex compat now defaults rather than receiving the removed per-ID rules (`crates/axo-ai/src/models/rules.rs:19-78,386-449`).
- Cache: `<cache_dir>/codex-models.json`, a JSON array of normalized camelCase objects `{id,name,contextWindow,image,efforts}`, not the full server response. It is shared at the cache-directory level, not keyed by account, and has no independent freshness timestamp. Read errors warn; a failed/no-credential refresh retains the loaded list. Therefore logout/account change does not itself clear this cached list (`crates/axo-ai/src/models/codex.rs:17-29,130-156`; `crates/axo-ai/src/models/mod.rs:99-106,550-583,603-651`). Cached listing is not an authorization guarantee.

### Loading, refresh, configuration, and failures

- `ModelsConfig` adds optional top-level **`refreshInterval`** (seconds; absent = 7200, zero disables the timer) and **`catalogUrl`** (absent = public v2 URL). Existing JSONC/comments/trailing commas and provider/model overrides remain (`crates/axo-ai/src/models/config.rs:13-38`).
- `Models::load` reads the Codex cache and models.dev cache when a cache directory exists. With a usable catalog cache it builds immediately, scheduling refresh according to catalog file age; it does not immediately discover Codex just because Codex cache is absent. Without catalog cache it awaits catalog/Codex gathering concurrently before building. First-fetch failure logs and continues without the catalog; floor/config models remain. The failed first fetch waits the next interval, not a retry loop (`crates/axo-ai/src/models/mod.rs:168-214,550-590`). An old v1-only cache therefore follows the new-cache-miss path.
- **`pub async fn refresh(&self) -> Result<(), Error>`** fetches catalog/Codex, reruns compatible custom-provider discovery, rebuilds in place, and retains runtime registrations. Catalog failure preserves the previous catalog/cache and returns an error, but Codex/discovery changes can still be published before that error is returned. Codex failures warn rather than failing refresh; custom discovery failures preserve prior model IDs (reconstructed with current config). A newly fetched catalog mapping to zero usable models is rejected. Cache-write failure warns but does not discard successfully fetched data (`crates/axo-ai/src/models/mod.rs:244-249,519-651,674-737`).
- The registry owns its timer via `tokio::spawn` and `tokio::time::sleep`, so an enabled timer requires a running Tokio runtime with time support. First refresh is after `interval.saturating_sub(cache_age)` (immediate if stale), subsequent waits occur after refresh completion. Reload replaces the timer; dropping `Models` aborts it. No timer for zero interval or no cache directory (`crates/axo-ai/src/models/mod.rs:251-275,483-490`).
- With **no cache directory**, startup reads/fetches neither catalog nor Codex cache and installs no timer; explicit refresh still performs authenticated Codex/custom-provider discovery but skips models.dev. Zero interval only disables the timer: it does **not** disable a first-fetch, explicit refresh, or post-login refresh (`crates/axo-ai/src/models/mod.rs:178-198,251-275,550-590`).
- Built-in `Models::login` stores credentials, then spawns a refresh after successful `openai-codex` login, except when a runtime registration replaces that provider. Login does not await catalog completion; refresh failure only logs. Normal refresh also skips built-in Codex discovery when registered replacement exists (`crates/axo-ai/src/models/mod.rs:397-423,519-529`).
- `reload(&self, config: ModelsConfig, extended_context: bool) -> Result<(), Error>` rebuilds from **already-loaded catalog/Codex data**, reruns custom discovery, preserves registrations, and restarts the timer; it does not re-read caches or fetch the catalog itself. On error the existing state stays. Changing `catalogUrl` does not itself purge data or immediately fetch when interval is disabled (`crates/axo-ai/src/models/mod.rs:216-242`).
- Every rebuild applies provider base URL/API/compat/headers, explicit model entries, then model overrides. Thinking maps merge by level, compat deep-merges, explicit tier vectors replace tiers, and absent fields preserve source values. Refresh does not erase user overrides (`crates/axo-ai/src/models/mod.rs:739-848`; `crates/axo-ai/src/models/config.rs:117-163`).

### Registry resolution and open sessions

- `0f4f890` changes request resolution: `auth` and streaming resolve the **current provider/id registry definition**, rather than using an arbitrary/stale passed model copy. Missing IDs fail with `UnknownModel`; in-flight requests keep their captured definitions. Config-base-URL provenance is tracked separately and passed into auth resolution, and a registered provider's request rewrite is kept separate from auth (`crates/axo-ai/src/models/mod.rs:340-349,426-480,739-848,856-913`). The owned `find() -> Option<Model>` / `all() -> Arc<[Model]>` API break originated in `54dccae`, not `614089b` (`crates/axo-ai/src/models/mod.rs:351-364`).
- `614089b` additionally keeps each session's applied registry definition. At the next request's `before_request`, **before automatic compaction**, a changed same-provider/id definition updates agent/session limits, prices, thinking support, and selection. A host-modified copy stays while the registry is unchanged. A removed model remains selected locally but its request fails `UnknownModel`; there is no automatic alternate-model selection (`crates/axo/src/session/mod.rs:1103-1161,1255-1267,2002-2010`).
- If adoption clamps thinking, the session durably appends the existing **`Entry::ThinkingLevelChange`**, then applies selection. Wire shape remains `type: "thinking_level_change"`, `thinkingLevel`, and flattened entry base. There is **no new entry variant, no model-change entry for metadata-only updates, and no new clamp-reason field**. Applying selection emits the existing context event when context usage exists (`crates/axo/src/store/entry.rs:259-285`; `crates/axo/src/session/mod.rs:876-881,1103-1161`).
- New test `sessions_follow_registry_changes_but_keep_host_copies` reloads a window from 200k to 50k, checks adoption on the next prompt and absence of model-change entries after the prompt, then sets a host 30k copy and checks retention on the next prompt. It does **not** assert thinking clamp journaling, timer operation, or Axome UI synchronization (`crates/axo/tests/session.rs:1010-1051`).

## 2. Where Axome touches it today

- **Engine/cache/config:** `Engine::build` creates `dirs.cache/axo`, passes it to both `ModelsOptions.cache_dir: Some(...)` and `Axo::builder(...).cache_dir(...)`, reads `dirs.models_path()` using `ModelsConfig::parse_jsonc`, and exposes parse/load error separately while falling back to default config. Thus Axome already enables the new catalog cache/timer; the Axo builder cache option is not the sole registry configuration (`src-crates/axome-core/src/services/axo/engine.rs:25-92`). `extendedContext` defaults false (`engine.rs:96-105`).
- **Lifecycle:** service `engine()` compares model-file mtime/length plus extended-context setting and constructs a replacement engine on changes. `invalidate()` drops the current service slot rather than calling in-place `Models::reload`. The existing “Reload Models” operation only invalidates that slot (`src-crates/axome-core/src/services/axo/mod.rs:295-338`; `src-crates/axome-core/src/operations/axo.rs:34-36`). [INFERENCE] This lifecycle is not equivalent to updating the registry retained by already-open sessions, and can leave old/new registries with distinct timer/config state.
- **Listing:** `available_models` checks auth once per provider, then projects selector/provider/name, supported thinking levels, window, and image support, sorting by provider/name. Its existing `for ... in models.all()` and `.all().filter(...)` assume the prior iterator API and need compatibility migration (`src-crates/axome-core/src/services/axo/mod.rs:680-714`; provider counts also iterate `.all()` in `services/axo/providers.rs:13`). `ChatModel` exposes no API/max-output/pricing-tier fields (`src-crates/axome-protocol/src/chat.rs:17-29`).
- **Frontend caching:** chat models are cached by folder, reused indefinitely unless forced, with explicit host/provider and settings-change reload paths. Settings `axoModels` loads once at component initialization. Neither is a subscription to registry refresh (`src/lib/features/chat/models.svelte.ts:10-66,76-93`; `src/lib/features/settings/state/axo.svelte.ts:6-25`).
- **Picker/settings surfaces:** composer derives current model/capabilities from cached catalog and effort from live session state; image warnings and effort options depend on cached model metadata (`src/lib/features/workbench/surfaces/chat/ChatSurface.svelte:39-52,333-353`). ModelPicker displays context windows (`src/lib/features/chat/elements/model-picker/ModelPicker.svelte:121,222`). Settings Models has default model/effort and role selectors, not catalog URL/interval controls (`src/lib/features/settings/views/ModelsView.svelte:28-35,57-138`). Providers shows model-file error/path, a native local “Open models.jsonc” control, and “Reload Models” (`src/lib/features/settings/views/ProvidersView.svelte:180-209`).
- **Clamp propagation:** backend converts the existing thinking entry to `ChatEntryBody::ThinkingChange` and derives selection from journal entries (`src-crates/axome-core/src/services/axo/convert.rs:689-691,782-799`). Live event handling updates thinking/model/window on these entries and broadcasts converted entries; context events independently update the window (`services/axo/live.rs:596-607,657-660,795-798`). Composer reads `chat.live.thinking`, so the existing event path can carry a clamp without a new wire variant (`ChatSurface.svelte:45-48,345-353`).
- **Transcript visibility:** `transcriptTurns` consumes thinking changes into turn configuration and steps, omitting pre-content selection entries; assistant config uses the latest thinking state. `AgentBlock` has no standalone thinking-change rendering branch. Thus a clamp is recorded and affects selection/config but is not a dedicated explanatory transcript notice (`src/lib/features/chat/turns.ts:125-158`; `src/lib/features/chat/elements/transcript/AgentBlock.svelte:169-258`).
- **Costs/context:** usage conversion keeps only `value.cost.total` (`src-crates/axome-core/src/services/axo/convert.rs:141`). Message Response Details shows this total; sidebar ContextPanel shows total/root/subagent cost; SessionSidebar summarizes cost (`src/lib/features/chat/elements/transcript/AgentBlock.svelte:340-359`; `src/lib/features/chat/sidebar/ContextPanel.svelte:309-312`; `SessionSidebar.svelte:75`). Existing model wire rows do not expose base/tier rates; prices are not recalculated by the frontend. Context stats accept live context-window updates (`services/axo/live.rs:795-798`; `convert.rs:833-841`).

## 3. What needs work in Axome

1. **Registry API compatibility, not a new model DTO schema — breaking.** Axome's iterator-style `all()` consumers must accommodate the snapshot API, and owned `find()` consumers fall under the same migration. No forced field migration exists for Model/InputKind/Cost/ChatModel; changed values arise from new sources. Surface: model/provider lists and capability-dependent controls. Open question: which additional metadata, if any, should be exposed beyond the existing window/images/effort fields?
2. **Catalog freshness across engine lifetime and frontend caches — compatibility.** Axo refresh now changes a living registry, while Axome replaces engines on reload and caches frontend lists independently. Open sessions only follow changes to their retained registry. Surface: existing chat model/effort/image controls, settings default/role/tool model choices, provider counts. Open questions: what freshness contract applies to each surface, and what should “Reload Models” mean (config rebuild versus network refresh)? No implementation is prescribed here.
3. **First-run/upgrade/offline behavior — compatibility.** The v2 filename causes a cache miss despite an old v1 cache; first load can await the 30-second catalog fetch and authenticated Codex discovery. Catalog failure is only a warning and can yield floor/custom-only availability, not `models_error`; without credentials the auth-filtered list can be empty. Surface: startup/new-chat loading, empty picker, provider/settings errors. Open questions: how should incomplete/offline catalog availability be distinguished from missing credentials or invalid config, and what network behavior is expected at first run?
4. **Refresh controls and configuration ownership — new capability.** Axome already passes parsed `models.jsonc`, so `refreshInterval` and `catalogUrl` become effective without a new typed settings field, but existing settings controls do not represent them. Timer-off is not network-off; explicit refresh errors may still accompany partial successful updates. Surface: Providers/Models settings and existing Reload Models action. Open questions: whether manual refresh, interval, alternate feed URL, freshness, or refresh errors need user-facing exposure, and which host's registry/config they describe.
5. **Account-dependent Codex membership and login completion — new capability/compatibility.** Actual account model lists replace the floor and refresh asynchronously after built-in login; credentials alone no longer define all catalog membership. Axome currently reloads its own list after provider changes, independently of an asynchronous catalog refresh. Cached Codex lists are not account-keyed and survive missing credentials/failures. Surface: login completion, provider model counts, model picker, saved default/role selectors. Open questions: when is login's model list considered settled, how should unavailable saved selections appear, and what account/cache provenance should users see?
6. **Changed capabilities and pricing semantics — compatibility.** Removed per-ID rules mean windows, efforts, images, APIs/compat, and displayed costs can differ after refresh; unknown newly discovered Codex prices can be zero. Public type shapes and cost math remain unchanged. Surface: effort picker/image admission/context display and usage-cost summaries. Open questions: whether zero/unknown catalog pricing must be distinguished, whether tier/extended-context pricing needs explanation, and whether refreshed capabilities require any visible indication.
7. **Automatic thinking clamp and model disappearance — compatibility/new behavior.** Existing entry/live-state plumbing carries clamped effort and updated context, but no cause field distinguishes refresh-driven clamps from manual changes, and cached picker options may disagree with the new live effort. Removed IDs stay selected and fail at request time. Surface: composer, response configuration, transcript, context sidebar, request-error display. Open questions: whether an automatic clamp needs explicit explanation, and how to communicate a removed selected model without implying automatic fallback. The upstream added test covers window adoption/host-copy retention only; clamp/event/UI behavior remains an integration verification concern.
