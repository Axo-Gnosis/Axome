# Provider/login/request-rewrite inventory — axo a0ec20d..614089b — 2026-11-20

Scope: all production changes in `54dccae`, axo-ai/Cargo changes in `0f4f890`, and their resulting contracts at `614089b`. References prefixed **axo:** are relative to `/repo/rust/axo` at `614089b`; **Axome:** references are relative to `/repo/rust/Axome`. Catalog-refresh additions from `614089b` are mentioned only where they affect this seam. Source inspection only; no builds, tests, live OAuth or network probes performed.

## 1. What changed in axo

### Registry and public metadata

- **Additive:** `Models::register(&self, provider: Provider) -> Result<(), Error>`; `Models::unregister(&self, provider: &str) -> bool`; `async Models::reload(&self, config: ModelsConfig, extended_context: bool) -> Result<(), Error>`; `async Models::login(&self, provider: &str, interaction: &dyn LoginInteraction) -> Result<(), Error>`. **Breaking:** `find(&self, selector: &str) -> Option<Model>` now owns the result; `all(&self) -> Arc<[Model]>` is a snapshot rather than an iterator of borrowed models. `find` splits at the first `/`, allowing `/` in model IDs. Sources: **axo:** `crates/axo-ai/src/models/mod.rs:219-245,278-354,392-415`.
- `Provider` is `Clone`, with `id: String`, `models: Vec<Model>`, `env: Vec<String>`, `requires_key: bool`, `login: Option<Arc<dyn ProviderLogin>>`, `rewrite: Option<Arc<dyn RequestRewrite>>`. ID must be nonempty and contain no `/`; all models must name that provider, with unique model IDs. Invalid registration returns `Error::Config` before mutating state. Registration replaces the previous registration wholesale, and shadows the loaded provider's models, environment variables, configured key/headers/overrides and built-in login. Unregister removes only the registration and reveals the loaded provider again; it does not delete credentials. Sources: **axo:** `crates/axo-ai/src/auth/provider.rs:13-25`; `crates/axo-ai/src/models/mod.rs:278-340,453-479`.
- **Breaking field rename/semantic generalization:** `ProviderInfo { id: String, env: Vec<String>, requires_key: bool, login: bool }` replaces `oauth` with `login`, meaning a `ProviderLogin` exists, not that login necessarily returns OAuth. `providers() -> Vec<ProviderInfo>` lists loaded plus registered providers, sorted by ID; registered entries override loaded metadata. `CredentialSource::{Config, ApiKey, Oauth, Env(String), None}` remains credential-source information, not a validation result. Sources: **axo:** `crates/axo-ai/src/models/mod.rs:41-59,356-389`; `crates/axo-ai/src/auth/provider.rs:30-36`.
- Registry snapshots contain unshadowed loaded models followed by registered models in provider-ID order. Reload builds a candidate before replacement, retains registrations, and leaves state unchanged on error. At `614089b`, reload uses the already-loaded catalog/Codex list, re-runs custom model discovery, restarts the refresh timer, and is serialized with refresh. A failed custom provider discovery retains previous model IDs. Reload is not a fetch of the remote catalog/Codex list; `Models::refresh()` is separate. Sources: **axo:** `crates/axo-ai/src/models/mod.rs:89-115,129-142,219-253,711-734`.
- **Behavior fix in `0f4f890`:** each `auth`/inference request resolves provider+model ID against the current registry, rather than using a stale caller model definition. Request snapshots retain the chosen provider/model/rewrite through an in-progress request; subsequent replacement/removal affects the next request. Missing model yields the newly added `Error::UnknownModel { provider: String, model: String }`, displayed as `Unknown model: <provider>/<model>`. This is the only new error enum variant in the assigned changes. Setup errors remain `Config`, `Auth`, `NoApiKey`, `Http`, `Io`, `Json`; stream failures become `AssistantEvent::Error`, not a new event type. Sources: **axo:** `crates/axo-ai/src/models/mod.rs:418-480,857-912`; `crates/axo-ai/src/error.rs:1-25`.

### Login interaction: exact API and cancellation contract

All traits below use `async_trait` and require `Send + Sync` (**axo:** `crates/axo-ai/src/auth/provider.rs:27-80`):

```rust
trait ProviderLogin: Send + Sync {
    async fn login(&self, interaction: &dyn LoginInteraction) -> Result<Credential, Error>;
    async fn refresh(&self, credential: Credential) -> Result<Credential, Error>;
}
trait LoginInteraction: Send + Sync {
    async fn open_url(&self, url: &str, instructions: Option<&str>);
    async fn device_code(&self, code: &DeviceCode);
    async fn prompt(&self, prompt: &LoginPrompt) -> Result<String, Error>;
    async fn select(&self, select: &LoginSelect) -> Result<String, Error>;
    async fn progress(&self, message: &str);
}
struct DeviceCode {
    user_code: String,
    verification_url: String,
    expires_in_seconds: Option<u64>,
}
struct LoginPrompt { message: String, placeholder: Option<String>, secret: bool }
struct LoginSelect { message: String, options: Vec<LoginOption> }
struct LoginOption { id: String, label: String }
```

All fields shown are public. Interaction data structs derive `Debug, Clone, PartialEq, Eq`. `open_url`/`device_code` return once displayed, never after user completion; `select` returns the option **ID**; `secret` instructs masking. A login may drop a pending prompt when no longer needed. **Cancellation is not an interaction enum variant, method, token, or new error variant:** the host drops the login future. Sources: **axo:** `crates/axo-ai/src/auth/provider.rs:31-80`; `crates/axo-ai/src/models/mod.rs:392-404`.

- `Models::login` resolves the currently registered/loaded provider, calls its login, then stores the returned `Credential` under that provider ID. Unknown provider: `Error::Config`; known provider without login: `Error::Auth`. At `614089b`, successful built-in `openai-codex` login also starts a background registry refresh; a registration shadowing that ID suppresses that built-in-specific follow-up. Sources: **axo:** `crates/axo-ai/src/models/mod.rs:392-438`.
- **Breaking removal:** public free functions `auth::codex::login` and `auth::codex::refresh` are replaced by `auth::codex::CodexLogin::new(reqwest::Client) -> Self` implementing `ProviderLogin`, and registry-owned login/refresh dispatch. `auth::codex::{PROVIDER, BASE_URL}` remain public. `CodexLogin` emits **only `open_url(url, None)` and one `prompt`** (`message = "Paste the redirect URL or authorization code"`, `placeholder = None`, `secret = false`). It emits no device-code, selection or progress calls. PKCE browser login binds `127.0.0.1:1455`; browser callback races the prompt. If binding fails, only manual input remains. Prompt error means no manual input; with a listener it keeps waiting for the callback. Inputs remain redirect URL, `code#state`, query string, or raw code. Sources: **axo:** `crates/axo-ai/src/auth/codex.rs:24-141,238-240`.

### Credentials, auth precedence and refresh

- `ModelAuth` still has `api_key: Option<String>`, `headers: BTreeMap<String, String>`, `base_url: Option<String>`; its shape is unchanged, but stored OAuth headers/base URL now populate it. `Credential::ApiKey { key: String }` is unchanged. **Rust source break:** constructing or exhaustively destructuring `Credential::Oauth` now requires accounting for `headers: BTreeMap<String,String>` and `base_url: Option<String>`, in addition to `access`, `refresh`, `expires: i64` (epoch milliseconds), and flattened `extra: Map<String, Value>`. Sources: **axo:** `crates/axo-ai/src/auth/mod.rs:17-51` (compared with `a0ec20d:crates/axo-ai/src/auth/mod.rs:15-41`).
- **On-disk compatibility:** JSON remains `{ "<provider>": { "type": "oauth", "access": ..., "refresh": ..., "expires": ..., ...extra } }`; API-key type remains `api_key`. New JSON keys are `headers` and `baseUrl`; omitted values default to empty/None and are omitted again when empty/None. Thus Axome's existing OAuth entries without these keys deserialize without a migration. Codex continues writing flattened `accountId` and now also writes `headers["chatgpt-account-id"]`; `baseUrl` is absent for built-in Codex. Old deserializers' flattened `extra` can retain the new keys, but the old request logic does not consume them as auth overrides. Sources: **axo:** `crates/axo-ai/src/auth/mod.rs:30-50`; `crates/axo-ai/src/auth/store.rs:1-19`; `crates/axo-ai/src/auth/codex.rs:208-218`; pre-pin credential definition cited above.
- Auth precedence: configured `apiKey` (including environment interpolation) wins, then stored credential, then first nonempty provider environment variable. A configured key returns before looking up OAuth. Configured headers beat stored headers case-insensitively. **`0f4f890` correction:** explicit config base URL also beats the credential's base URL; otherwise credential base URL overrides the model default. Provider registration bypasses the loaded provider's config entirely. Caller `SimpleStreamOptions.headers` subsequently overrides auth headers and can delete defaults with `None`. Sources: **axo:** `crates/axo-ai/src/auth/resolve.rs:119-207`; `crates/axo-ai/src/models/mod.rs:453-479,738-845`; `crates/axo-ai/src/api/mod.rs:102-125`.
- Refresh no longer special-cases Codex: any provider with `ProviderLogin` can refresh an OAuth credential when `now_ms() + 5*60*1000 >= expires`. A provider without login errors when refresh is needed; it does not silently keep the expiring token. Refresh receives the **whole credential**, under `CredentialStore::update`'s exclusive cross-process lock. It re-reads after acquiring the lock, reuses another refresh's fresh result, and respects logout. A spawned update owns lock/refresh/persistence so cancellation of the requesting stream cannot lose a rotated token before storage. `CodexLogin::refresh` rejects non-OAuth credentials and applies a 15-second token-request timeout. Sources: **axo:** `crates/axo-ai/src/auth/resolve.rs:27-28,168-170,210-247`; `crates/axo-ai/src/auth/mod.rs:53-70`; `crates/axo-ai/src/auth/codex.rs:38,121-140`.
- **Account ID behavior:** built-in Codex login/refresh still requires extracting a nonempty ChatGPT account claim from the access-token JWT, and persists both legacy `accountId` and the new header. The **wire adapter**, however, no longer rejects a non-ChatGPT/non-JWT key for lacking that claim: extraction is an optional default; configured credential/caller header can replace or remove it. Other tokens send no derived account header. Protocol headers such as Authorization still apply after configured headers, before any rewrite. Sources: **axo:** `crates/axo-ai/src/auth/codex.rs:208-235`; `crates/axo-ai/src/api/codex.rs:73-112`.

### Request rewriting and other source breaks

- **Additive seam:** `ProviderRequest { url: String, headers: reqwest::header::HeaderMap, body: serde_json::Value }`; `RequestRewrite: Send + Sync` has `async fn rewrite(&self, model: &Model, request: ProviderRequest) -> Result<ProviderRequest, Error>`. It changes the already-built request, not the standard response parser. `StreamOptions` adds `rewrite: Option<Arc<dyn RequestRewrite>>`; explicit old struct literals require that field. `Clone`, `Default`, custom `Debug` remain; its previous `PartialEq` derivation is removed. Sources: **axo:** `crates/axo-ai/src/api/mod.rs:84-145`.
- Anthropic Messages, OpenAI Completions and Codex Responses all run rewrite once before transport retries and serialize the returned JSON. Completions explicitly supplies content-type before rewrite. A failed or cancelled rewrite sends no request; failures flow through existing stream error handling. There is no response-rewrite hook, discovery rewrite, new journal entry, or serialized rewrite request in this seam. Sources: **axo:** `crates/axo-ai/src/api/http.rs:101-131`; `crates/axo-ai/src/api/anthropic.rs:212-240`; `crates/axo-ai/src/api/completions.rs:1134-1162`; `crates/axo-ai/src/api/codex.rs:45-64`; `crates/axo-ai/src/models/mod.rs:711-719,857-912`. The runtime-provider documentation explicitly confirms discovery exclusion and non-journaling: **axo:** `crates/axo/docs/configuration.md:410-421`.
- No new `models.jsonc` keys originate in `54dccae`/`0f4f890` for registering login/rewrite implementations: these are Rust runtime objects, not config-serialized callbacks. The scope's persistence change is OAuth fields, not a session journal or event schema change. The later catalog commit's `refreshInterval`/`catalogUrl` and session model adoption are separate inventory topics; reload/login behavior above reflects final HEAD.
- `54dccae` also migrates axo's selector resolution/examples to owned `find`, changes its login example to the generic interaction interface, adds provider regression coverage and `testing::read_http_request_parts`, and updates adapter tests for `StreamOptions.rewrite` and credential headers. `0f4f890` adds the `axo-ai` self dev-dependency with feature `testing` and corresponding self-entry in Cargo.lock; it adds no production dependency. `54dccae` changes no Cargo files. At HEAD, `bytes.workspace = true` is additionally present from the later catalog commit, not this provider seam. Sources: commit diffs; **axo:** `crates/axo-ai/Cargo.toml:10-35`; `crates/axo-ai/src/testing.rs:99-145`; `crates/axo/src/config.rs:187-202`.

## 2. Where Axome touches it today

- **Registry ownership/rebuild:** `Engine` holds `Arc<Axo>` and `Arc<Models>`. `Engine::build` parses models.jsonc, calls `Models::load` with shared file credentials/cache and no custom HTTP client, falls back to default config while retaining `models_error` on parse/load failure, and constructs a new `Axo`. **Axome:** `src-crates/axome-core/src/services/axo/engine.rs:12-92`. `AxoService::engine` compares models-file modified-time/length and global extended-context flag; a missing engine or changed stamp builds a new entire Engine. `invalidate()` only clears the cached engine. **Axome:** `src-crates/axome-core/src/services/axo/mod.rs:295-338`.
- **Credentials/reload mutations:** the one file store is `<data>/axo/auth.json`, shared with WebTools. Set-key and remove-key write/remove credentials then invalidate. Removal does not unregister a model provider. Login completion invalidates on both success and failure. `axo_models_reload` merely invalidates; rebuilding happens on the next engine access. **Axome:** `src-crates/axome-core/src/services/axo/mod.rs:219-245`; `providers.rs:48-72`; `login.rs:68-86`; `src-crates/axome-core/src/operations/axo.rs:34-35`.
- **Registry reads:** `engine.rs:19-22` uses `find` only to read context_window (owned return is already compatible). `providers.rs:12-35` directly iterates old `all()`, counts models using borrowed provider names, and accesses removed `provider.oauth`. `mod.rs:685-708` directly iterates `all()` and calls `.all().filter(...)`; it checks `Models::auth` once per provider to determine model-picker availability, potentially refreshing credentials. These all/snapshot consumers need migration; this is distinct from rewriting the compatible context-window lookup.
- **Login lifecycle:** Codex-only guard in `login.rs:39-43`; one active login slot per service. Starting another login aborts and awaits the old task to release the loopback listener. Old `auth::codex::login` receives a new HTTP client, shared store, URL callback and one-shot manual redirect future (`:45-67`). Start waits at most ten seconds for a URL and fails if none arrives (`:97-118`). Submit consumes the one-shot (`:122-137`). Status is Pending/Done/Failed; observing a terminal result removes it (`:140-151`). Cancel aborts and awaits (`:19-29,154-158`). There is no arbitrary interaction queue or typed device-code/selection/progress transport.
- **RPC/Tauri/frontend boundary:** `src-crates/axome-protocol/src/axo.rs:12-18,38-51` exposes `oauth: bool`, start `{loginId,url}`, and status tagged `state` with `pending|done|failed {message}`. Commands are declared in `src-crates/axome-protocol/src/rpc.rs:636-652`, exposed through core operations `src-crates/axome-core/src/operations/axo.rs:13-52`, registered by `src-tauri/src/commands/mod.rs:246-254`, and invoked with host/folder routing by `src/lib/api/backend.ts:682-704`.
- **Settings › Providers:** `src/lib/features/settings/views/ProvidersView.svelte:26-39,53-65` fetches provider status/counts and refreshes chat models after changes. Readiness is source != none or no required key, not validated authorization. The view shows credential-source badges, OAuth badge and login/logout based on `provider.oauth`, plus key controls (`:75-95,239-289`); file-open/reload and config errors are at `:180-205`. Login automatically opens returned URL, polls every second, exposes one redirect input, and cancels on modal close/destroy (`:67-72,117-176,331-367`). It cannot currently render generic prompt labels/placeholders/secrets, device codes, selections or provider progress.
- **Independent web auth:** `WebTools` holds the shared credentials and its own HTTP client, not Models (`src-crates/axome-core/src/services/axo/web/mod.rs:35-66`). Dedicated search credentials use `web:*` keys and separate status/set/remove paths (`web/auth.rs:16-66,78-124`; `web/mod.rs:105-144`). Grounded search dispatch accepts only anthropic/openai/openai-codex/google (`web/providers.rs:115-135`). It resolves credentials outside Models and silently skips unavailable auth; these are separate from runtime provider enumeration.
- **Duplicate Codex refresh / transport assumptions:** `web/auth.rs:127-183` implements another five-minute expiry check, locked reread and `codex::refresh(&http, refresh)` call (`:160`, now removed). Other grounded providers use stored credentials/env directly, without generic refresh. `web/grounded.rs:5,208-245` uses still-public Codex BASE_URL, hardcodes `/codex/responses`, reads legacy `extra.accountId`, and ignores credential `headers`/`base_url`; it builds its own request and bypasses Models/config/rewrite. New built-in Codex credentials still include accountId, so that particular lookup is not immediately broken. Generic registered-provider request/auth behavior does not automatically reach these host tools.

## 3. What needs work in Axome

1. **Caller compatibility — breaking.** Migrate removed Codex login/refresh calls, renamed provider metadata and changed `all()` ownership/iteration consumers identified above. The context-window `find` consumer already tolerates ownership. Review any explicit `StreamOptions`/OAuth construction or exhaustive error handling when adopting the new library contracts; the grounded credential matches shown above use `..` and do not themselves break for added fields. Surfaces: provider/model lists, login and grounded search. No UI redesign is implied by the Rust ownership change.
2. **Generic login capability versus Codex-only flow — breaking baseline plus new capability.** Existing Codex login must use the new API; supporting other runtime logins additionally requires a host interaction contract that can represent URL instructions, device-code expiry, masked prompts, option IDs, progress and dropped pending prompts. Current mandatory first URL, ten-second URL deadline and single redirect response do not represent all legal ProviderLogin implementations. Codex itself only needs URL + nonsecret prompt. Surfaces: Providers login dialog and local/remote RPC. Open questions: which interaction kinds are in Axome's adoption scope, and what is the supported behavior when a login has no initial URL or asks multiple questions? Cancellation remains future-drop; it is not a new wire event supplied by axo.
3. **Login metadata semantics — breaking field, new capability.** `login` describes an available login implementation, not necessarily OAuth; the current wire field, OAuth badge, and OAuth-source-only logout branch encode the narrower assumption. Providers can return API keys as well as OAuth credentials. Surface: Settings provider cards and provider protocol types. Open question: what login-capability and credential-source semantics should Axome expose independently? No additional built-in OAuth providers are introduced by this commit; other logins require runtime registrations.
4. **Registry lifetime/reload behavior — compatibility and new capability.** The new API can mutate the existing Models instance and retain registrations; Axome currently discards the Engine after credentials/manual reload and replaces it for config changes. `reload` addresses config/key-driven discovery; `register` addresses runtime contributions, not stored-key mutation. These are now available lifecycle operations, not proof that every Engine rebuild is interchangeable. Existing fallback-on-invalid-config differs from reload's keep-last-good behavior; remote catalog fetch differs from config reload. Surfaces: Reload Models, config-error display, model picker and open chats. Open questions: should open sessions share one evolving registry, what should invalid config preserve/display, and what exactly should the current Reload Models action refresh? Source-level opportunity only; no replacement architecture is prescribed here.
5. **Web tools' independent auth/refresh — breaking and compatibility.** Replace the removed refresh entry point while accounting for the whole-credential refresh contract, cancellation-safe rotation, new headers/baseUrl and generic provider ownership. Built-in Codex's retained accountId makes the current header lookup compatible, but does not make custom credential headers, endpoint overrides or provider rewrites apply to grounded search. Surfaces: grounded fallback behavior and Settings › Tools' provider/model selection. Open question: are host grounded requests expected to honor the same provider auth/config/rewrite contract as chat, and which runtime providers, if any, are valid grounded backends? The request-rewrite seam alone does not add web-search response parsing for new providers.
6. **Runtime providers/request rewrite — new capability, not an automatic extension system.** The host can now register/replace/unregister model sets, login handlers and per-request URL/header/body transformations. Registration shadows all loaded provider config and login until removal; unregister is distinct from credential logout. Surfaces potentially affected: provider/model catalog, provenance/config expectations and errors in existing chats. Open questions: whether/when Axome accepts runtime contributions, who owns registration lifetime, and how replacement/removal is communicated. Bun loading, extension install/management and additional subscription providers are not shipped by this seam.
7. **Changed registry failure and request identity — compatibility.** A removed model now fails with UnknownModel without an outgoing request; a changed definition is used at the next inference boundary. Surfaces: selected model availability and chat error presentation. Open question: how should an already-selected but no-longer-registered model be represented? No new journal/event format is needed solely for UnknownModel; it travels through the existing assistant error path.
8. **Credential persistence — compatibility, no mandatory file conversion.** Existing auth.json OAuth/API-key entries remain readable; new OAuth fields and legacy accountId coexist. Credential consumers outside Models need to distinguish preserved extra metadata from authoritative request headers/base URL. Surface: existing account continuity and credential source/status, not a requirement to relog users. Open question: what compatibility guarantees does Axome require if older and newer consumers share the same auth.json? No live login/refresh compatibility has been exercised in this survey.
