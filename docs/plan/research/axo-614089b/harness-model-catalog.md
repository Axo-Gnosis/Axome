# Other harnesses: model catalog, refresh, effort and pricing

## Evidence boundary

Inspected upstream HEAD snapshots, not the versions contemporary with Axome's old pin. Commit-pinned references below are the primary evidence. In particular, **pi and OMP are no longer static-catalog-only**, and **current OpenCode no longer implements the old `opencode models --refresh` interface**. No harness was executed; UI statements below are traced rendering/handler behavior, not interactive observations. Claude Code evidence is its mutable official documentation, not a public implementation; no private startup/cache mechanism is inferred from it.

Sources: [OpenCode `504a7b3`](https://github.com/anomalyco/opencode/tree/504a7b3054491b99fc1b11cf83be6fae836ef77c), [pi `06a2036`](https://github.com/badlogic/pi-mono/tree/06a20368a74233e21725511a3268742e3dea65c3), [OMP `fbb8085`](https://github.com/can1357/oh-my-pi/tree/fbb8085ff432419132c6e3132f36ad857893b1a4), [Codex `0a0b102`](https://github.com/openai/codex/tree/0a0b1021f06dffda763bdafbee32e25c04cac20b), [Zed `3463950`](https://github.com/zed-industries/zed/tree/34639504475cef1677149ad351b3788a89dba865).

## C1 — First-run/upgrade catalog network wait

### Evidence

- **OpenCode: snapshot floor, background refresh.** `populate` reads explicit local file, persisted cache, then bundled snapshot; network is the last fallback only if snapshot is disabled/unavailable. The bundled snapshot is committed and can be replaced with a live catalog during release builds. Default source is now `https://models.opencode.ai/experimental/v2.0/api.json?type=chat,decision,image,video`, not the old models.dev v1 URL. Cache is versioned and custom-source-keyed. Refresh starts in a forked task and repeats five minutes after each completion; HTTP timeout 10s, transient retries, ETag revalidation. Failure logs and is ignored, leaving the boot floor intact. Explicitly turning snapshot off changes the contract to awaiting fetch. [catalog lifecycle](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/core/src/models-dev.ts#L484-L705).
- **pi: bundled generated models plus persisted remote overlay and provider discovery.** `ModelRuntime.create` loads `models.json`, a file-backed `models-store.json`, bundled providers, and wraps most providers with a pi.dev overlay; OpenRouter instead personalizes the catalog to the key. Creation awaits a refresh but **network is opt-in** (`allowModelNetwork === true`); `PI_OFFLINE` disables model networking. The runtime supports caller deadlines. Static provider catalogs remain the baseline, newer remote catalogs overlay them. Cache restore occurs before auth/network resolution. [runtime creation](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/core/model-runtime.ts#L218-L268), [overlay](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/core/remote-catalog-provider.ts#L110-L194), [cache-first provider refresh](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/ai/src/models.ts#L573-L625). This is an SDK creation contract, not a claim that every pi launch path chooses identical options.
- **OMP: local hydration before validation, background network after first frame.** Bundled catalog + custom configuration + SQLite-backed discovery caches. `hydrateCredentialScopedModelCaches` is explicitly local-only/best-effort, awaited at startup so account-scoped cached models exist before validating selectors. `refreshInBackground` does online reconciliation separately; comments identify interactive launch as waiting until first frame. RPC consumers can explicitly await that background operation for a complete answer. [startup/cache contract](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/coding-agent/src/config/model-registry.ts#L982-L1140).
- **Codex: bounded cache-aware reads plus background refresh, not one universal blocking policy.** Default cache TTL 300s; manager exposes InMemory, Offline, OnlineIfUncached and Online strategies. Initialize/OnlineIfUncached try cache before fetch. The endpoint has a 5s deadline and uses provider-owned `/models` (Codex backend base URL gives `/backend-api/codex/models`); provider config may supply `model_catalog_url`. Default catalogs have bundled fallback; explicit-provider catalogs intentionally suppress that fallback. App-server starts a worker which refreshes immediately, then every 4m30s. Do not describe the TTL as the poll interval. [manager policy](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/models-manager/src/manager.rs#L43-L157), [fallback/load](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/models-manager/src/manager.rs#L760-L864), [endpoint deadline](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/model-provider/src/models_endpoint.rs#L49-L169), [background worker](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/app-server/src/models_refresh_worker.rs#L10-L59).
- **Zed: provider-specific async loading.** Registry authenticates providers in background for selector population; already-initialized providers get `refresh_models`. OpenRouter starts fetch after credential load/save, replaces its in-memory available-model vector only on success, then notifies observers. This is not evidence of a universal disk cache/TTL or bundled fallback for every Zed provider. [registry](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_model/src/registry.rs#L545-L618), [OpenRouter state](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_models/src/provider/open_router.rs#L47-L144).
- **Claude Code:** aliases resolve according to provider/account/version; `/model` selects an alias or full ID. Documentation says mistyped startup `--model`/environment/settings values need not block session startup: the first request reports the selected-model problem. It does not establish a fetch/cache startup contract. [official model configuration](https://code.claude.com/docs/en/model-config#setting-your-model).

### Options seen

1. Bundled snapshot immediately, background best-effort replacement (OpenCode; OMP also has local cache hydration).
2. Cache-only construction, network explicitly chosen by host or picker (pi runtime).
3. Strategy-controlled bounded await when uncached, plus separate background worker (Codex).
4. Provider-owned async authentication/discovery rather than one global feed (Zed).

No universal startup blocking behavior is forced by these precedents; a usable offline floor and account-authoritative discovery are separate concerns.

## C3 — Manual refresh, interval, URL, freshness and error affordances

### Evidence

- **OpenCode:** current `models` command has only shared server flags and lists model IDs; its handler does not call refresh. Therefore `opencode models --refresh` is **not a current-HEAD affordance**. Service still offers `refresh(force)` internally. Configuration accepts URL/file/fetch/snapshot options; CLI server forwards `OPENCODE_MODELS_URL`. Five-minute TTL/loop and ETag are internal, with `updatedAt` metadata; inspected app model tooltip has no freshness field. Refresh failures log rather than propagate (`Effect.ignore`). [command specification](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/cli/src/commands/commands.ts#L329-L332), [handler](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/cli/src/commands/handlers/models.ts#L10-L24), [options/refresh](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/core/src/models-dev.ts#L479-L705), [CLI environment forwarding](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/cli/src/server-process.ts#L110-L125).
- **pi `/model`:** render current snapshot immediately; refresh asynchronously with 15s overall picker timeout. Visible messages distinguish “Refreshing model catalogs…”, success, timeout using cached models, one-provider or multi-provider refresh failures, and configuration error. Reopening is a refresh trigger, **not necessarily a forced network fetch**: pi.dev overlay checks a four-hour freshness interval, ETag, and bundled generation date; request attempt timeout is 4s. Base URL is configurable through runtime options (`catalogBaseUrl`); no demonstrated Settings URL field. [picker](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/modes/interactive/components/model-selector.ts#L157-L227), [remote feed policy](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/core/remote-catalog-provider.ts#L14-L16), [freshness gating](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/core/remote-catalog-provider.ts#L140-L191).
- **OMP model hub:** opening reconciles in background; hovering/selecting a provider auto-refreshes at most once per process (120ms debounce), **F5 forces provider refresh**. A spinner tracks pending providers. Explicit refresh can also re-mint command credentials; passive discovery deliberately does not. Empty-state messages include cached list age (“less than a minute ago” / “Nm ago”), discovery failed, endpoint 404 with baseUrl guidance, unauthenticated, idle, authoritative empty and success. These are actual scoped empty-state messages, not proof of an always-visible global freshness badge. [refresh/status UI](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/model-hub.ts#L1093-L1219).
- **Codex:** automatic worker + cache TTL + ETag-based invalidation; matching ETag renews cache TTL without rebuilding. Catalog failures log; no manually exposed catalog-refresh button/command or freshness timestamp was established in inspected UI. Custom endpoint is provider configuration, not a demonstrated feed Settings widget. [ETag handling](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/models-manager/src/manager.rs#L774-L799).
- **Zed:** concrete provider-level **Refresh Models** icon in Ollama configuration, next to Connected; it clears fetched rows and retries connection. Disconnected state instead offers Connect. LM Studio and llama.cpp also implement refresh affordances, but do not extrapolate to a global refresh button for all providers. OpenRouter retains/logs last fetch error separately. [Ollama UI](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_models/src/provider/ollama.rs#L1078-L1111), [OpenRouter error retention](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_models/src/provider/open_router.rs#L127-L143).
- **Claude Code:** `/model` and version-following aliases are documented; no public catalog-refresh interval, feed URL, or freshness UI contract was established. Changing API base URL routes requests, not model identity. [official docs](https://code.claude.com/docs/en/model-config).

### Options seen

- Automatic internal refresh with logs (OpenCode/Codex).
- Opening picker refreshes with explicit progress and cached-result errors (pi).
- Provider-scoped refresh + F5 + contextual age/error states (OMP).
- Provider setup-page refresh button (Zed local providers).
- Endpoint override as advanced runtime/config option, not mandatory general Settings control (OpenCode/pi/Codex).

## C4 — Keeping frontend lists current

### Evidence

- **OpenCode backend:** successful changed-body refresh invalidates memoized catalog and broadcasts `ModelsDev.Event.Refreshed`; unchanged body/304 avoids churn. Models-dev plugin subscribes, reloads integrations then providers, and re-reads after subscribing to close the cold-start lost-event race. This proves backend propagation, not the complete app transport contract. [publication](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/core/src/models-dev.ts#L672-L704), [consumer/race closure](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/core/src/plugin/models-dev.ts#L76-L89).
- **pi picker:** snapshot-on-open, refresh-in-background, reload snapshot on completion; preserves the currently highlighted model by identity after rows change. The inspected picker is not an always-live general registry subscription. [picker update](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/modes/interactive/components/model-selector.ts#L157-L227).
- **OMP:** refresh completion invokes `onCatalogRefreshed`, updates scope if needed, then re-reads registry state; refresh rows do not need another network call. Login flow explicitly logs in then reopens model hub. Registry mirrors receive discovery state/catalog and recompose already-materialized snapshots immediately. [hub callback](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/model-hub.ts#L1150-L1176), [login reopening](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/coding-agent/src/modes/controllers/selector-controller.ts#L1201-L1210), [mirror update](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/coding-agent/src/config/model-registry.ts#L951-L979).
- **Codex:** model manager exposes a watch receiver for successful provider refreshes/invalidation (not cache-only reads); changed auth invokes a bounded best-effort refresh. Successful fetch publishes an `Arc<RefreshedModelCatalog>`; access-revoked explicit provider publishes invalidation. This is a backend subscription primitive, not proof that every model popup is live-updating. [watch API](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/models-manager/src/manager.rs#L164-L195), [auth refresh](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/models-manager/src/manager.rs#L654-L682), [publish](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/models-manager/src/manager.rs#L884-L965).
- **Zed:** provider state is observable; successful fetch calls `cx.notify`. Agent model picker obtains `selector.watch()`, fetches initial list and selected model concurrently, then repeats on each receiver notification. This is direct evidence of live picker updates. [provider observation](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_model/src/language_model.rs#L717-L731), [picker watcher](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/agent_ui/src/model_selector.rs#L66-L98).
- **Claude Code:** docs specify model/alias/account behavior, not UI cache invalidation internals; no event contract claimed.

### Options seen

1. Registry event/watch -> dependent state rebuild (OpenCode/Codex backend; Zed through picker).
2. Picker-owned snapshot refresh on open/completion with selection preservation (pi).
3. Explicit refresh/login completion callbacks and reopening (OMP).

These are not interchangeable with reloading only the server registry: each visible consumer still needs an update path.

## C5 — Offline/incomplete vs unauthenticated vs invalid configuration

### Evidence

- **OpenCode:** feed outage is a logged best-effort refresh failure, separate from the availability floor. Legacy `disabled_providers` is translated into explicit `provider.use` deny policies; `enabled_providers` becomes default deny plus allows. Therefore missing/hidden provider is not evidence that catalog fetch failed or credentials are missing. [policy conversion](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/core/src/config/normalize.ts#L410-L429). The catalog refresh does not itself present an offline warning.
- **pi:** picker reports remote refresh failures as using cached models, separately from `modelRuntime.getError()` config errors. Public pi.dev overlay deliberately uses `refreshModelsAuth: "configured"` so a stale provider login does not block public metadata refresh. Cache is restored before auth resolution; provider-specific discovery can still fail independently. [picker errors](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/modes/interactive/components/model-selector.ts#L188-L224), [auth separation](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/core/remote-catalog-provider.ts#L126-L140).
- **OMP:** strongest explicit state vocabulary in examined UI: `cached`, `unavailable`, `unauthenticated`, `idle`, `empty`, `ok`, plus configuration errors. An authoritative successful zero-model result is not called offline. 404 gets endpoint-specific guidance; unauthenticated tells user authentication is required. Background discovery pending is also separately queryable. [empty-state mapping](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/model-hub.ts#L1179-L1219), [pending API](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/coding-agent/src/config/model-registry.ts#L1076-L1102).
- **Codex:** failed fetch is explicitly **not** authoritative empty: retains last successful snapshot and original freshness. Exception: explicit provider catalog with 401/403 or rejected credentials clears models/ETag, invalidates persisted snapshot, publishes invalidation. Identity checks prevent old account/provider snapshot reuse. A default bundled fallback and an explicit account-authoritative provider have intentionally different failure behavior. [failure branches](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/models-manager/src/manager.rs#L866-L965).
- **Zed:** background registry treats CredentialsNotFound separately from connection refused and other errors; OpenRouter has both authentication state and last-fetch error. Failed refresh preserves the previous vector; no key clears available models. However storing an error is not proof it is displayed in the picker. [registry errors](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_model/src/registry.rs#L573-L611), [provider branches](https://github.com/zed-industries/zed/blob/34639504475cef1677149ad351b3788a89dba865/crates/language_models/src/provider/open_router.rs#L98-L143).
- **Claude Code:** unavailable and restricted selections are not one behavior. Docs: `/model` rejects allowlist-blocked switches; blocked startup override is replaced with default and warning; aliases may substitute newest permitted family version with notice. Typo at startup can instead wait until first request to error. Current SDK/app `setModel` confirms unrecognized IDs with provider on first switch and refuses unavailable IDs immediately. This is not a documented offline catalog mechanism. [restrictions](https://code.claude.com/docs/en/model-config#restrict-model-selection), [switch/startup validation](https://code.claude.com/docs/en/model-config#setting-your-model).

### Options seen

- Silent best-effort metadata fallback (OpenCode).
- Cached results + refresh error in picker (pi).
- Typed provider states with distinct actionable empty/error copy (OMP).
- Preserve snapshot on transport outage but invalidate on explicit access rejection (Codex).
- Distinct authentication/error model even when UI reporting is quieter (Zed).
- Reject unavailable explicit switch, warn/substitute only selected startup/alias cases (Claude Code).

## C6 — Thinking/effort clamp and notification

### Evidence

- **pi:** `supportsXhigh` is superseded by metadata-driven `getSupportedThinkingLevels`/`clampThinkingLevel`. Non-reasoning => off; explicitly mapped null excludes a level; xhigh/max require mapping. Unsupported request searches upward first, then downward: this is **not universally a downward clamp**. Session model switch reapplies thinking via `setThinkingLevel`, records effective change and emits `thinking_level_changed`; requested global default is only changed on explicit persist. UI event invalidates footer/editor border, not a dedicated downgrade warning. Cycle-model status includes effective thinking in “Switched to … (thinking: …)”. [algorithm](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/ai/src/models.ts#L1312-L1343), [session changes](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/core/agent-session.ts#L2726-L2808), [UI event](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/modes/interactive/interactive-mode.ts#L3686-L3689), [cycle notice](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/modes/interactive/interactive-mode.ts#L4777-L4789).
- **OMP:** model switch reapplies current thinking/auto to new capabilities and hard per-session ceiling. Effective change is journaled and emits `thinking_level_changed`; auto retains separate configured intent. Event handler updates status/border/render, not a special “reduced because model changed” notice. [session clamp](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/coding-agent/src/session/model-controls.ts#L547-L614), [UI reaction](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/coding-agent/src/modes/controllers/event-controller.ts#L480-L503).
- **Codex:** conversation-model default resolution retains configured effort only if target supports it, else uses target default then first non-Ultra supported effort. This helper does not produce a clamp notice. Interactive model picker offers **supported effort options**, often a second choice step; one ordinary effort is applied directly. Max/Ultra require an explicit extra step to avoid accidental expensive selection. Certain high/xhigh options show rate-limit warning. [default fallback](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/tui/src/app/config_persistence.rs#L1147-L1176), [effort picker](https://github.com/openai/codex/blob/0a0b1021f06dffda763bdafbee32e25c04cac20b/codex-rs/tui/src/chatwidget/model_popups.rs#L512-L568). This does not prove all request paths silently sanitize unsupported effort.
- **Claude Code:** current docs describe per-model saved effort (`modelSettings`), supported-model effort slider, `/effort status`, and transient footer/header indication. Per-model defaults avoid blindly carrying a global selected level to every model. Unsupported capability mapping specifics were not established; do not extrapolate pi's algorithm. [effort docs](https://code.claude.com/docs/en/model-config#adjust-effort-level).
- **OpenCode/Zed:** no universal numeric clamp/notification contract established in this pass; variant/provider-specific systems should not be described as implementing pi's ladder.

### Options seen

1. Automatic capability clamp + effective-state display/event, no special explanation (pi/OMP inspected handlers).
2. Target default fallback plus explicit supported-effort picker (Codex).
3. Per-model saved preference/default (Claude Code).

Evidence supports separating **requested preference** from **effective effort**; it does not force a toast. Any Axome explanation should name actual adjustment, not assume it was always a reduction.

## C7 — Unknown/zero prices, tiers and extended context

### Evidence

- **OpenCode:** missing/unsupported token-price record normalizes to zero input/output/cache. Context-only overrides become tier entries; other conditions are not preserved by this normalization. Thus zero is not proof of free. App `isFreeModel` is provider-specific: `opencode` and missing cost or input=0 -> free badge; other providers are not globally tagged free by that predicate. Inspected model tooltip presents context/capability information, not a tiered price table. [normalization](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/core/src/models-dev.ts#L318-L362), [free predicate](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/providers/models/models.tsx#L19-L28), [badge](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/providers/models/select-dialog.tsx#L211-L218), [context tooltip](https://github.com/anomalyco/opencode/blob/504a7b3054491b99fc1b11cf83be6fae836ef77c/packages/app/src/providers/models/tooltip.tsx#L121-L150).
- **pi:** `/model` rows show ID, distinct name, provider, current/default markers; inspected rows have **no cost/context columns**. Footer shows context percentage/window and accumulated cost; cost is omitted when zero except subscription sessions, which show `$… (sub)`. This is usage accounting, not a catalog unknown-price explanation. [picker rows](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/modes/interactive/components/model-selector.ts#L324-L364), [footer](https://github.com/badlogic/pi-mono/blob/06a20368a74233e21725511a3268742e3dea65c3/packages/coding-agent/src/modes/interactive/components/footer.ts#L160-L204).
- **OMP:** model browser has explicit `Ctx` and `$/M` columns and details/previews for input/output/cache. Explicit metadata pricing states render **free / included / varies / unknown**, with “pricing unknown” in detail; invalid numeric legs render `?`. Important limitation: **undeclared** zero/missing token rates still use legacy free convention, except nonzero subscription credits. No claim that this metadata issue is solved for every provider. [price formatting and columns](https://github.com/can1357/oh-my-pi/blob/fbb8085ff432419132c6e3132f36ad857893b1a4/packages/tui/src/overlays/model-browser.ts#L821-L918).
- **OMP extended context:** default-off Settings toggle **Extended Context**, description “Use larger context windows where supported; may incur premium pricing. Off keeps default or standard-pricing windows”. Registry applies advertised max when enabled; otherwise caps at `longContext.inputThreshold` (comment gives 272K example) so compaction occurs before premium price tier.
