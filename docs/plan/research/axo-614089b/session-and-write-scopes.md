## 1. What changed in axo

### Layered write enforcement: behavior/security fix plus breaking Rust and journal contracts

- **Previously:** `effective_writes` collapsed the agent, mode, and inherited ceiling into one lexical intersection of strings. `intersect` kept the narrower spelling of each overlapping pair; path and URL strings never overlapped. Only the surviving roots were subsequently resolved to real paths during `check_write`. Thus the result was not necessarily the real-path intersection of all original restrictions (`a0ec20d:crates/axo/src/tools/writes.rs:32-74,91-132`; old `session/policy.rs:48-68`). A narrower lexical root that was a symlink could resolve outside the broader root which had already been discarded. Conversely, independently spelled aliases, or a path and file-backed URL referring to the same location, could collapse to an empty intersection despite permitting the same real target.
- **Now:** public `WriteScope { layers: Vec<Vec<WriteRoot>> }`, with `WriteRoot::Path(PathBuf)` and `WriteRoot::Url(String)`, retains the individual restrictions. `effective_writes` normalizes the agent/persona (or child spec), then effective mode, then inherited layers, removing exactly equal duplicate layers. A target must match at least one root in **every** layer. No layers means unrestricted; any empty layer denies all. Unknown schemes/empty entries normalize away, never granting access (`crates/axo/src/tools/writes.rs:12-56,102-142`; `session/policy.rs:49-75,180-222`). This is agent ∩ effective mode ∩ inherited ceiling, enforced at the target rather than by lexical pre-intersection.
- Files: both the target and each candidate root use `file_key`; a URL root must resolve to a file location before its real path can match. Therefore file-backed URLs and ordinary paths can satisfy the same layer. Virtual targets: only same-scheme URL prefixes on segment boundaries match; `..` segments reject the target. `local://` remains symbolic and resolves in each child's session. These remain point-in-time checks, not protection against another process swapping symlinks after checking (`tools/writes.rs:58-71,97-142`). The new regression explicitly denies `plans/linked/unlisted.md` where `plans/linked` escapes the parent ceiling, denies a file allowed only by the parent layer, and accepts an outside-spelled alias resolving into both layers (`tests/spawn.rs:654-738`). Single-layer real-path/symlink checking and virtual `..` rejection already existed; the fix is preservation and enforcement of all layers, not the first introduction of symlink checking.
- Error shape stays `"<target> is outside the write scope (<entries>)"`, or `"<target> is outside the write scope (no writes allowed)"`. The entries now describe the **first rejecting layer**, rather than a flattened intersection; order is agent, mode, inherited ceiling after deduplication. Files display their URL when present, otherwise path; virtual targets display their URL (`tools/writes.rs:73-84,110-138`). This is the `ToolError` returned to host `check_write` callers and built-in file tools; no new denial event/type is introduced.
- **Breaking Rust APIs:** `ToolScope::writes: Option<Vec<String>>` → `Option<WriteScope>`; `SessionTools::write_scope() -> Option<WriteScope>`; `SpawnLink::writes: Option<WriteScope>`; `SpawnContext::writes: Option<&WriteScope>`. `check_write(&Located) -> Result<(), ToolError>` is unchanged. `ModeSpec::writes` and `AgentSpec::writes` remain `Option<Vec<String>>`; frontmatter syntax does not change. `SessionTools` stores the layered scope; session initialization and spawn resolution pass references to it, rather than string slices (`session/policy.rs:19-30`; `tools/writes.rs:87-102`; `store/entry.rs:112-120`; `session/spawn.rs:155,248,401`; `session/mod.rs:1886-1890`; `tools/mod.rs:81`). `WriteRoot` and `WriteScope` are exported from `axo::tools` and the crate root (`tools/mod.rs:63`; `lib.rs:65`).
- **Breaking persisted header shape:** transparent serialization is now `"writes":[[{"path":"/absolute/root"},{"url":"local://"}]]`, not an array of strings. Missing or `null` remains unrestricted. `[[]]` is deny-all. Legacy nonempty string lists fail deserialization; `[]` is explicitly rejected with `"a persisted write ceiling must contain at least one layer"` because previously it meant deny-all and must not become unrestricted. There is no legacy conversion. `FORMAT_VERSION` remains **1** (`tools/writes.rs:13-37`; `store/entry.rs:21,112-138,731-757`). The `store/entry.rs` additions are this type/deserializer plus tests: **no new Entry variants or Submission fields** in this commit. Existing journals without an inherited write ceiling remain compatible with this particular change; scoped child headers do not.
- **Bash is separate and unchanged:** any read-only agent/mode/inherited bash ceiling yields `BashAccess::ReadOnly`; `rescope` installs bash access and write scope together but does not derive one from the other. Built-in bash still allows `/tmp`, `/dev/null`, session `local/`, and absolute existing `TMPDIR`; write-scope layers do not constrain its shell writes (`session/policy.rs:33-46,195-222`; `tools/bash.rs:154-180`). The inherited ceiling remains independent of later parent mode changes (updated regression `tests/spawn.rs:610-650`).

### Queued delivery: breaking withdraw result, additive metadata, race/reentrancy fixes

- `Session::withdraw(&str)` now returns `Result<QueuedInput, Error>`, not `Result<Vec<PromptPart>, Error>`. `QueuedInput` gains `custom: Option<SubmittedCustom>` alongside submission ID, kind, and parts. `QueuedInput::find` copies metadata from the already-existing `Entry::Submission.custom` field; this is a live Rust API addition, not a new journal field (`session/mod.rs:399-434`; `session/delivery.rs:494-528`). Rust struct literals must supply the new field.
- Host `post` messages retain `custom_type` and `display` in queue snapshots and withdrawal results. Their text must be resubmitted through `Session::post` to remain a custom host message, rather than becoming ordinary user input through `steer`/`follow_up`. `post` itself still builds a single text part plus a custom agent message (`session/delivery.rs:533-577`). The new test checks withdrawn host metadata and ordinary input's `custom == None` (`tests/session.rs:480-515`).
- Withdrawal now acquires `queue_order` before looking up/removing a queued message. This closes the window where a submission entry has been journaled/published but not yet inserted into the agent queue: submission uses the same lock across append and enqueue (`session/delivery.rs:506-508,645-675`). It remains detached from caller cancellation; successful withdrawal writes the same `SubmissionWithdrawn` tombstone; delivered/already-withdrawn/non-agent-queued inputs still fail `NotQueued`.
- If tombstone persistence fails, the message is still restored at its kind's queue tail, but now the lock is released and `claim_idle` → `release_or_deliver` is attempted before returning the error. This prevents restored work remaining stranded on an otherwise deliverable idle session. It does not lift auto-pause; held input remains held (`session/delivery.rs:514-525,162-167`).
- `release_or_deliver` still makes the queue-drain/idle decision under the activity ownership lock, retaining running ownership when another run is needed. It now collects the next delivery/input inside that lock and rebuilds prompt input **outside** it, because rebuilding can call host tools. Previously `run_input`/`start_delivery` could execute while the activity lock was held. The shared `spawn_run` helper centralizes identical spawning/logging. This is a reentrancy/deadlock avoidance fix, not a new queue order or event format (`session/delivery.rs:119-132,198-242`).
- `resume_wakes` itself is unchanged: clears auto-pause and, if idle can be claimed, drains held input/job results. Stop/failure holding, new user input lifting the pause, steer-before-follow-up behavior, foreground bash promotion, and steers settling ask/review waits are not new features in this commit. `queue_message` still excludes Quiet/Mail from lifting auto-pause; `enqueue` still routes FollowUp vs Steer/Prompt vs Mail/Quiet separately (`session/delivery.rs:580-586,645-675,788-803`). The changed internal `submission` helper now receives provenance directly instead of mutating it afterward; existing journal provenance is preserved, not a new field (`session/delivery.rs:636-640,808-830`).

### Other changed contracts

- **Mode review wire/journal keys:** accepted `yield` details rename `original_result`/`accepted_result` to **`originalResult`/`acceptedResult`**. `result` still contains the accepted value, and `mode`/`outcome` are unchanged. This changes newly recorded generic JSON details, without an Entry version bump or rewrite of older details (`session/modes.rs:660`). Tests now assert complete expected objects and persistence across reopen (`tests/modes.rs:860-874,981-990,1007`). Rust acceptance APIs and review state transitions are unchanged.
- **Process capture API:** new `Pipe::{Stdout, Stderr}` and `PipeChunk { pipe: Pipe, bytes: Vec<u8> }`; `Process::capture_output()` now yields `mpsc::Receiver<io::Result<PipeChunk>>` plus `JoinSet<()>`. This is a breaking API for direct pipe-capture clients, making the previously unreachable `Merged` origin unrepresentable. `OutputChunk { stream: OutputStream, bytes }` remains the replay/read-log type; its `Merged` variant remains valid for logs without sidecars (`exec/host.rs:47-75,542-547,636-650`; `lib.rs:38`).
- **Command spooling:** `write_spool` consumes `PipeChunk`, with exhaustive stdout/stderr matching instead of an unreachable merged branch. Numeric stream tags merely become constants: stdout=1, stderr=2, end=3, failed=4; 9-byte records remain eight-byte little-endian end offset plus tag. No log/sidecar encoding change, no changed retained-output API, no changed capture ordering or error semantics (`jobs/command.rs:183-190,225-229,295-302,919-927,962-985`). Tests convert captured pipe chunks to replay chunks when comparing (`jobs/command.rs:1223-1235`).
- **Turn-change squash:** blob re-diffs now run with bounded concurrency **8**, and results are assigned back by original index, retaining first-file-appearance order. Eligibility remains multi-mutation, stored nonbinary first-before/last-after; read failure logs a warning and leaves no diff. Single-mutation diffs are retained directly; created files diff from empty bytes (`tools/changes.rs:21,232-269`). No `FileChange`, `SquashedChange`, snapshot layout, `record_change`, `details.change`, or `details.ledger` schema change. The pure `squash` code is unchanged; its comment now accurately says net reverts are dropped **unless created or discontinuous** (`tools/changes.rs:193-229`). New assertions cover mixed single/multiple mutations, creation, and result order (`tools/changes.rs:339-357`). This is performance/clarification, not a new net-change behavior.
- **Documentation scope:** `extending.md` reflects the above scope/withdraw/capture/result-detail contracts; `prompts-and-context.md` replaces lexical intersection with per-layer real-path enforcement and narrows the claim from “before any I/O” to before target-content access; `sessions-and-compaction.md` documents unsupported legacy child write ceilings and custom queue metadata. `configuration.md` changes describe runtime providers/login/reload from `axo-ai`, not an additional session/write-scope config feature; those APIs belong to the provider survey. The committed `plan/design.md` write-scope bullet likewise changes from flattened intersection to separate layers and typed persisted roots; its other edits and `plan/plan.md` host-capability edits concern the provider request-rewrite seam. The Phase 3 bullet still records inherited write ceilings. None of the uncommitted extensions/Bun roadmap is shipped behavior.

This concerns children created under Axome's bundled planning/research restrictions, not merely third-party configurations. Open question: what compatibility expectation applies to those already persisted sessions? No migration is supplied by these axo changes.

The effective scope now genuinely preserves all real-path layers; aliases can become allowed where lexical intersection wrongly denied them, and symlink escapes become denied. No new Axome policy/workaround is needed; P18's bash scratch exception remains unchanged. 6. **Update the stale queue handoff contract; retain existing queue/snapshot/output behavior — documentation compatibility.** `handoff/axo-steer-queue.md:25` still claims a parts-vector return. Delivery fixes do not remove the need for abort→idle→resume, nor change ordinary queue ordering/holding. No redundant Axome workaround was identified in these scoped integrations.
