# Service tiers in Axome chat

2026-11-22 · axo `deda8e6` · Axome `48f5a03`  
**Question (T13/Q66):** Where should someone choose Flex, Fast or Ultrafast, see the cost consequence before sending, and later tell which tier a response used?

**Put Service Tier in the existing composer effort popover.** Keep model, reasoning effort and processing priority independent. Show the model’s estimated price factor **before** selection and the recorded tier **after** each response. Neither is a promise of actual latency or an invoice.

## The three values Axome must not collapse

| Value | Authority | Example: Fast chosen, model changes under Keep |
|---|---|---|
| **Chosen** — durable session preference | axo `crates/axo/src/session/mod.rs:2462-2472,3148-3158,3240-3249` | Fast remains chosen. It's not a host-global switch. |
| **Effective** — what axo can request on this model | `crates/axo-ai/src/model.rs:113-123` | Standard if Fast is not sendable. Even a declared Anthropic Messages Flex factor doesn't make Flex sendable. This is what the composer should lead with. |
| **Recorded** — tier on this assistant message | `crates/axo-ai/src/types.rs:80-115`, `api/responses.rs:714-722`, `api/completions.rs:1242-1273`, `api/anthropic.rs:324-340` (adapter paths under `crates/axo-ai/src/`) | Provider echo when available, otherwise axo’s effective request tier. It can differ from the composer, even without a model switch. Don’t label it “provider verified.” |

The [tier survey](providers-credentials-and-tiers.md#service-tiers-capability-selection-persistence-billing) documents the adapters and feed rules. The UX consequence: **use the catalog factor to compare future options; use the message total to explain past spend**. axo chooses context-window rates, then applies the served-tier factor to input, output and cache costs (`crates/axo-ai/src/cost.rs:8-39`). Discovered Codex support can carry `1.0` when the feed has no matching factor (`crates/axo-ai/src/models/rules.rs:465-518`). There is no factor snapshot or known-price bit on the message. “1× catalog rate” is valid; “no extra credits,” “free,” and recomputed historical factors are not.

## Recommendation

**1. One composer trigger, two independent controls.** `src/lib/features/workbench/surfaces/chat/ChatSurface.svelte:326-357` already puts `ModelPicker` next to `EffortPicker`; `ChatSurface.svelte:160-162` cycles effort, and `src/lib/features/chat/elements/model-picker/EffortPicker.svelte:53-65,86-146` owns the slider/popover. Generalize that popover to **Model Options** where tier is applicable; retain the effort glyph, stops, shortcut and gesture unchanged. Keep `Alt+M` for models. No tier cycling on Shift+Tab. Within the popover: existing **Reasoning Effort** slider; underneath, **Service Tier** as keyboard-selectable single-choice rows. These are categorical choices, not stops on the same slider. Keep tier available independently on a non-reasoning model. Retain an effort-only presentation in forms editing `defaultThinkingLevel` alone.

- List `Standard · 1×`, then **only sendable** Flex/Fast/Ultrafast in that order with their model-specific factors, e.g. `Flex · 0.5×`, `Fast · 2×` (illustrations, not constants). Column label **Estimated cost vs Standard**; helper “Applies from the next model request.” Never imply a fixed throughput improvement. For a standard-only model show one quiet line `Standard only on this model`, not three dead options. If the catalog is unavailable/loading don't misreport “Standard only.”
- Closed composer: ordinarily just the existing effort label. For nonstandard effective tier append muted text, e.g. `high · Fast`. If chosen differs, `high · Standard (Fast unavailable)`; inside, “Fast is remembered. Requests use Standard on this model.” Keep **Use Standard** actionable to clear the remembered tier even when Standard is already effective. Support is conveyed in words; accessible name includes effort and tier; ordinary focus, no flashing bolt or new status dot. Read-only history has no active control.
- **No auto-upgrade, model swap or hidden write.** A bare model selection goes to axo without an added tier: same model retains choice; different model resets by default; Keep carries the chosen tier and can reactivate it on a later supported model. An explicit suffix (including `:standard`) wins. Show the new effective state after the host confirms; report errors through existing command error UI. `/tier fast` etc. stays discoverable in command suggestions and usable mid-run; menu invokes the same built-in command path, not a new preference API. The command is Alongside, not a mutation of a request already in flight (`crates/axo/src/config.rs:215-231`, `commands.rs:154-159,291-297`, `session/mod.rs:3148-3158`).

**2. Preserve selectors through editing and launch.** `src/lib/features/chat/elements/model-picker/selector.ts:15-45`, `ModelPicker.svelte:71-95` and `SelectorPicker.svelte:34-59` currently drop or forbid role suffixes and only recognize one effort suffix. Make these shared utilities read/write a base plus optional effort and optional tier; omit unset suffixes, preserve explicit Standard, emit canonical `base:effort:tier`, accept either order. Match a known whole model ID first, then check catalog prefixes as each suffix is removed, as axo does; `vendor/model:fast` can be a literal ID. Recognize `:fast` on its own and `@review:flex:low`; reject duplicate suffix kinds and distinguish an unknown raw custom selector from a resolved model. Preserve unrecognized/unavailable custom text verbatim on display/open; let axo resolve when used. Validate the **role name**, not the whole reference. No role-to-role definitions; referencing a role elsewhere can override its stored effort/tier independently (`crates/axo/src/config.rs:287-385`).

- `src/lib/features/settings/views/ModelsView.svelte:59-79,91-111`: role assignments get the same options popover in the existing `SelectorPicker` field variant. A selector field has **No override** (no suffix) *and* **Standard** (explicitly defeat an inherited tier); selecting/clearing one dimension never loses the other. When a field names a role, preview its resolved defaults, not a rewritten concrete model. The default-model selector may likewise carry a tier; `defaultThinkingLevel` stays a separate fallback, not a tier setting. Apply the shared selector editor to subagent model fields, not just roles. No global “last tier used.”
- `src-crates/axome-core/src/services/axo/mod.rs:809-829,850-893` currently strips selector details; `src/lib/features/chat/controller.svelte.ts:125-133` and `services/axo/mod.rs:896-914` then create using bare model + effort. Preserve the intended default/role selector **through creation**, resolving against the host’s actual fallback model when a selector supplies only suffixes. Carry resolved model, effort and tier for role previews separately from editable selector text. Don’t write a paid session override into the host’s last-model fallback or issue a second `/tier` after creation.

**3. Give policy its existing Settings homes.** `docs/plan/design.md:39,65` (D4/P6) requires full Settings coverage on the selected host’s global layer. In **Settings → Models → Defaults**, add **Tier on model change** (`Reset to Standard` / `Keep chosen tier`, default Reset). In **Settings → Tools → Subagents** (`src/lib/features/settings/views/ToolsView.svelte:174-200`), add **Subagent tier** (`Standard` / `Inherit parent tier`, default Standard). Description: “Applies when the child’s model selector does not specify a tier. Inheriting can increase cost.” Reuse SettingsSection/SettingRow and `ui/select` as in `AxoChoiceRow.svelte:12-16`. Bind to `axo.serviceTier.onModelChange` and `axo.subagents.serviceTier`; extend `src-crates/axome-protocol/src/axo_settings.rs:9-35` and typed defaults/schema. Never expose these as project overrides, even in a trusted project (`crates/axo/src/config.rs:670-677`); Inherit uses the parent’s **chosen** tier and the child's model still gates application (`crates/axo/src/session/spawn.rs:419-433`). Keep custom `serviceTiers` definitions/overrides in the existing Settings-accessible `models.jsonc` editor per P6; surface its parse/reload diagnostics. No second pricing form or tier preference for compaction: summarization stays Standard (`crates/axo/src/compaction/summary.rs:370-380`).

**4. Let the host project capability, axo project reality.** Add typed `ServiceTier` and a sendable nonstandard tier→catalog factor map to `ChatModel`, preserving Standard implicitly; build it from each resolved `Model` using `effective_tier`, not a frontend provider-name table. Carry chosen and effective on the live selection, including initial attach; derive both from the same axo selection snapshot. Add recorded tier to assistant entries, not to `ChatUsage` aggregates. Wire Rust protocol (`src-crates/axome-protocol/src/chat.rs:19-48,127-135,264-296,551`), shared desktop/server projections, corresponding frontend types and chat reducers together. Axome's journal converter and attach/replay paths (`src-crates/axome-core/src/services/axo/live.rs:587-644`, `mod.rs:2133`, `convert.rs:134-142`) must cover tier-only changes and the optional tier on thinking changes. Treat a missing optional co-change as **unchanged**, not reset. Reproject on model/mode changes, extension actions, registry refresh, forks and reconnects; use the session model for effective state, not a potentially stale global catalog. Keep any picker capability refresh on the existing host catalog invalidation path; the missing registry change signal is tracked separately. No migration or second client-side session store.

**5. Tell the truth at turn granularity without decorating every bubble.** The existing footer already pools all assistant requests but prints the *last* model beside effort (`src/lib/features/chat/elements/transcript/AgentBlock.svelte:91-126,311-369`). Append `· Fast` etc. only for uniformly nonstandard recorded requests, `· Mixed tiers` for more than one recorded value, nothing for all Standard/no assistant. In **Response Details**, show the recorded tier even for Standard; for mixed turns list requests in transcript order with model, recorded tier and that message’s stored estimated USD. Use a focusable, scrollable details popover instead of an unbounded hover tooltip when listing requests. No invented historical multiplier. Example: user sets `/tier fast` during a tool call; one Standard and one Fast assistant entry yield **Mixed tiers**, not a Fast label for the whole turn. The same rule holds when provider echo differs from the request. Failed/aborted entries are not proof of a charged request: label these as recorded estimates, never “billed.” `src/lib/features/chat/sidebar/ContextPanel.svelte:292-313` already separates cumulative root/subagent spend; leave that arithmetic alone and explain in its info text that estimates include recorded tier pricing. Never multiply the displayed dollars again or apply the root tier to a tree or compaction row.

**Decision checks for implementation:** (1) a literal colon ID, role override, suffix-only selector and explicit Standard survive editor→save→new session; (2) Fast → unsupported under Keep → supported reactivates Fast, while clearing it on the middle model prevents that; (3) one live, one reopened and one remote client agree after `/tier` and a combined effort/tier change; (4) mixed-tier turn totals equal the recorded message sums even after catalog repricing; (5) child defaults and compaction never silently inherit premium processing.

**Alternatives rejected**

- Separate always-visible tier button: adds permanent footer width for a model-dependent choice.
- Fast on/off switch or tier-as-effort: loses Flex and Ultrafast, conflates processing priority with reasoning, and makes relative price hard to compare.
- Model aliases per tier: duplicates the catalog and makes a priority change look like a model change with its own reset policy.
- Slash-only or Settings-only control: conceals support and the estimated price at the point of commitment.
- A multiplier on every historical message or the session total: axo did not record a historical factor; a turn/tree can span several tiers and prices.

## Needs Toph

None. The existing model/effort interaction, exhaustive Settings decision and axo’s tier policy suffice.
